## Состояния

`intake -> validation -> clarification -> normalization -> description -> approval -> render_export -> delivery_acceptance`

Состояние `approval` применяется только к диалоговому режиму в Лисе: пользователь после описания структуры выбирает изготовление презентации или редактирование структуры.

При запуске другим агентом DataCanvas после проверки достаточности и безопасности данных пропускает ручное подтверждение и переходит к подготовке презентации.

Для `CO-2026-001` — принятого изменения приоритета продукта — канал доставки файла принят: готовая презентация отправляется пользователю по электронной почте. Состояние `delivery_acceptance` закрывается после отправки файла и фиксации очищенного статуса доставки; при запуске другим агентом вызывающий агент получает статусы и сведения о результате.

## Контур Q4_2026

`eligible -> validating -> rejected_retryable` описывает непринятый запрос:
после исправления он может снова пройти проверку, но заказ и отправка до принятия
не создаются. Адреса проверяются только через «Профиль сотрудника».

`validating -> accepted_locked -> generating` фиксирует единственный заказ для
пары сеанс/пользователь. После `accepted_locked` повторный запрос отклоняется.

После `generating` допустимы `delayed`, `delivery_partial` или
`delivery_confirmed`. Безопасное состояние возвращается в тот же чат без
системного PUSH. В `delivery_confirmed` кнопка недоступна до завершения сеанса.
`delayed`, `delivery_partial` и неподтвержденная или ошибочная доставка переходят
через `support_pending` в `session_closed`; новый заказ в закрытом сеансе не
создается. Число повторов и канал сопровождения не определены этим контрактом.
