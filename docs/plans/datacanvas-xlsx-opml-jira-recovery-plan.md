Если готовый OPML или пакет импорта не найдены, подготовить безопасный план восстановления цепочки на основе сохраненного Excel-источника без изменения продуктового смысла DataCanvas.

## Уже Найденные Следы

В текущем репозитории найден документ `docs/datacanvas-documentation-implementation-plan.md`. Он фиксирует прежний замысел и критерии работы:

- Excel `bl-value-rm-data-canvas.xlsx` был основным источником stories, приоритетов, сроков и оценок.
- `stories.opml` был историческим источником ранних формулировок.
- `docs/stories.md` должен был покрыть Excel-строки 4-25 и сопоставить их с 14 OPML-stories.
- OPML использовался для трассировки, а Excel считался более свежей детализацией.

Во время первоначального поиска в текущем каталоге `docs/stories.md` уже был раздел трассировки Excel/OPML, но сам исходный `stories.opml` в рабочем дереве и в списке файлов веток найден не был.

На 13 июля 2026 года в индексе восстановления зафиксированы только безопасные метаданные обнаруженного внешнего OPML: предоставленный SHA-256 — контрольный отпечаток, 14 ранних верхнеуровневых пользовательских историй и отсутствие ресурсных значений. Отпечаток не подтверждён чтением локального файла; локальный путь и содержимое OPML не сохраняются. Пакет Jira и сопоставление полей подготовлены и согласованы для ручного импорта, но фактический импорт не выполнялся и не заявляется.

## Границы Работы

Разрешено:

- искать исходники и следы конвертации в текущем репозитории, ветках, истории Git и связанном репозитории `AI-agent-platform`;
- сравнивать найденные OPML/Jira-артефакты с сохраненным Excel;
- фиксировать результаты в документации, реестре источников и evidence;
- предлагать восстановление OPML/Jira-пакета, если готовые артефакты не найдены.

Запрещено без отдельного решения Product Owner:

- менять смысл stories, приоритетов, сроков, оценок или бизнес-ценностей;
- заполнять Jira custom fields догадками;
- считать пакет Jira готовым без согласованного mapping;
- вручную редактировать generated artifacts;
- заменять текущий каталог stories найденным историческим OPML.

## План Работы

1. Зафиксировать Excel как исходник продукта.
   - Проверить контрольную сумму сохраненной копии.
   - Убедиться, что путь зарегистрирован в `product-source-registry.json`.
   - Убедиться, что оригинальный бинарный файл отсутствует в Git, а очищенная копия исключена из человекочитаемой навигации.

2. Проверить текущий репозиторий.
   - Поискать `stories.opml`, `.opml`, `.xlsx`, Jira CSV/JSON, конвертеры и scripts во всем рабочем дереве.
   - Проверить `docs/datacanvas-documentation-implementation-plan.md`, `docs/stories.md`, backlog, traceability и source registry.
   - Составить список того, что уже перенесено из Excel/OPML в текущие Markdown/JSON-артефакты.

3. Проверить историю Git текущего репозитория.
   - Поискать удаленные или незакрепленные файлы через `git log --all --name-only`.
   - Проверить коммиты, где менялись `docs/stories.md`, `docs/product/requirements/user-stories.md`, backlog и traceability.
   - Проверить stash, если он относится к работе с источниками, без восстановления чужих изменений.

4. Проверить соседние ветки.
   - Отдельно проверить `codex/q3-priority-impact-plan`.
   - Проверить любые новые локальные или удаленные ветки, появившиеся после последнего `fetch`.
   - Для каждой ветки сохранить вывод: найдено / не найдено / требуется ручная проверка.

5. Проверить `AI-agent-platform`.
   - Сделать отдельный ограниченный клон или использовать уже существующий локальный клон, если он появится.
   - Искать только по релевантным путям: backlog, import, Jira, OPML, XLSX, DataCanvas.
   - Не переносить артефакты из другого репозитория без проверки происхождения и актуальности.

6. Сравнить найденные артефакты с Excel.
   - Проверить покрытие Excel-строк 4-25.
   - Проверить соответствие 22 stories `DC-ST-01` - `DC-ST-22`.
   - Проверить трассировку к 14 OPML-stories, если OPML будет найден.
   - Отдельно отметить строки, где бизнес-ценность отсутствовала в Excel и требовала уточнения.

7. Подготовить решение по дальнейшему действию.
   - Если готовый OPML найден: сохранить его как исторический source artifact, зарегистрировать в source registry и связать с текущей трассировкой.
   - Если найден готовый Jira import package: проверить mapping и статус готовности через Jira field mapping gate.
   - Если готовых артефактов нет: предложить восстановить OPML и Jira CSV из сохраненного Excel через отдельный генератор/скрипт с проверками.

8. Провести проверки.
   - `npm run validate:product-sources`
   - `npm run validate:product-source-consistency`
   - `npm run generate:docs-navigation -- --check`
   - `npm run validate:docs-navigation`
   - При появлении Jira-пакета: `npm run validate:jira-field-mapping`

## Ожидаемый Результат

После выполнения плана должно быть понятно:

- где находится сохраненный Excel-источник;
- был ли найден прежний OPML;
- был ли найден прежний пакет импорта в Jira;
- какие части работы уже отражены в `docs/stories.md`;
- какие артефакты нужно восстановить или сгенерировать заново;
- какие решения Product Owner нужны перед импортом в Jira.
