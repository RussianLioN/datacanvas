# План Prompt-Only Согласования И Редактирования Артефактов Проектной Документации

Навигация: [DataCanvas](../../README.md) / [Документация](../README.md) / [Планы](README.md) / Prompt-only согласование артефактов

Статус: draft
Владелец: Process Owner
Проверка: `npm run validate:docs-navigation`, `npm run validate:artifact-registry`, `npm run validate:artifact-hashes`

## Назначение

План описывает реализацию workflow — рабочего процесса — который запускается одним текстовым запросом пользователя и ведет согласование, просмотр, редактирование и проверку артефактов проектной документации DataCanvas как текущего документационного репозитория.

Workflow работает только с проектной документацией и документальным сопровождением. Он не определяет поведение продукта DataCanvas, не принимает продуктовые решения, не выводит требования из технических файлов и не превращает содержимое артефактов в правила самого процесса.

Пользователь не запускает `npm` команды вручную. Агент сам читает состояние, показывает текущий артефакт, дает кликабельные ссылки на исходные и производные файлы, предлагает варианты правок, фиксирует решения, обновляет документационные источники, запускает генераторы и проверки.

## Ключевые Изменения

1. Ввести boundary contract — контракт границы workflow:
   - workflow управляет только артефактами проектной документации;
   - продуктовые утверждения считаются содержимым проверяемых документов, а не инструкциями workflow;
   - любые изменения смысла продукта оформляются как предлагаемая правка документа и требуют явного согласования владельца;
   - технические контракты нельзя выводить из Vision — видения продукта, BMC — Business Model Canvas, бизнес-модели продукта, историй или требований без отдельного согласованного ADR — architecture decision record, архитектурного решения, JSON Schema — схемы данных, или contract artifact — контрактного артефакта;
   - бизнесовые утверждения нельзя выводить из ADR — architecture decision record, архитектурного решения, JSON Schema — схем данных, scripts — скриптов, или generated artifacts — автоматически созданных файлов.

2. Добавить prompt-only runbook — инструкцию запуска одним текстовым запросом:
   - стартовый prompt — текстовый запрос — читает состояние workflow, журнал, каталог артефактов и текущий маршрут согласования;
   - агент показывает пользователю текущий шаг, чек-лист, ссылки на артефакты, текущий текст раздела, варианты решений и влияние выбора;
   - агент сам выполняет генерацию и проверки после согласованных правок;
   - пользователь отвечает только на смысловые вопросы согласования.

3. Добавить artifact link catalog — каталог ссылок на артефакты:
   - хранить относительные пути, тип артефакта, источник истины, производные файлы, команду генерации, команду проверки и политику редактирования;
   - для BMC — Business Model Canvas, бизнес-модели продукта, обязательно связывать Markdown-источник, PlantUML — текстовую диаграмму, SVG — векторное изображение, PNG — растровое изображение, PDF — файл просмотра, и evidence — доказательства проверки;
   - в persisted files — сохраняемых файлах — не хранить абсолютные локальные ссылки;
   - в runtime chat — текущем ответе чата — строить абсолютные кликабельные ссылки на основе текущего рабочего каталога.

4. Добавить artifact review session state — состояние сессии согласования:
   - текущий маршрут согласования;
   - текущий артефакт;
   - показанный пользователю набор ссылок;
   - ожидаемое решение пользователя;
   - принятые, отклоненные и отложенные правки;
   - список generated artifacts — автоматически созданных файлов, ожидающих перегенерации;
   - последние результаты проверок.

5. Добавить artifact edit decision ledger — журнал решений по правкам:
   - кто согласовал;
   - какой артефакт изменяется;
   - какой текущий текст был показан;
   - какие варианты были предложены;
   - какой вариант принят или отклонен;
   - какие производные файлы обновлены;
   - какие проверки прошли.

6. Усилить правила UX — пользовательского опыта — в чате:
   - перед каждым вопросом показывать чек-лист шагов;
   - показывать текущий текст изменяемого раздела до вопроса;
   - давать не менее пяти готовых вариантов формулировки, если согласуется текст;
   - рядом с кодированными элементами давать расшифровку в той же строке;
   - показывать ссылки группами: source — исходник, derived — производные файлы, evidence — доказательства, navigation — навигация;
   - не предлагать пользователю принимать сырой JSON как основной текст решения.

7. Обновить контракты и проверки:
   - добавить JSON Schema — схему данных — для каталога ссылок на артефакты;
   - добавить JSON Schema — схему данных — для состояния prompt-only сессии;
   - расширить профильный валидатор проверками наличия всех путей, отсутствия абсолютных путей в сохраняемых файлах, корректной политики редактирования generated artifacts — автоматически созданных файлов;
   - добавить проверку, что производные файлы BMC — Business Model Canvas, бизнес-модели продукта, покрыты каталогом ссылок;
   - добавить проверку, что runbook содержит границу workflow и не содержит продуктовых правил как обязательных правил процесса.

8. Обновить документационные входы:
   - добавить README-раздел о запуске prompt-only workflow;
   - добавить локальный runbook для агента;
   - добавить ссылку на каталог артефактов из навигации;
   - зарегистрировать новые файлы в navigation source — ручном источнике навигации;
   - обновить artifact registry — реестр артефактов — и hash manifest — манифест хешей — через существующие генераторы.

9. Реализовать поток редактирования generated artifacts — автоматически созданных файлов:
   - если пользователь просит изменить SVG — векторное изображение, PNG — растровое изображение, PDF — файл просмотра, или PlantUML — текстовую диаграмму, агент определяет исходник;
   - показывает источник и производные ссылки;
   - предлагает правку источника обычным русским текстом;
   - после согласования меняет источник;
   - запускает генератор;
   - запускает профильные проверки;
   - показывает ссылки на обновленные производные файлы;
   - фиксирует решение в журнале.

10. Реализовать поток остановки и продолжения:
    - при обрыве агент сначала читает состояние сессии и журнал решений;
    - продолжает с последнего открытого вопроса;
    - повторно показывает чек-лист, текущий артефакт и ссылки;
    - не переходит к изменению продукта без явного решения пользователя.

## Граница Разделения

- DataCanvas в этом плане — текущий репозиторий проектной документации, а не реализация продукта.
- Workflow не содержит правил поведения продукта DataCanvas.
- Product Owner или другой назначенный владелец остается единственным источником явного согласования продуктового смысла.
- Продуктовые утверждения отображаются только как содержимое артефактов или предложенные правки.
- Любые продуктовые изменения требуют явного решения владельца и фиксируются как документационное решение.
- Абсолютные локальные ссылки допустимы только в ответах чата; в сохраняемых документах, схемах и журналах используются относительные пути.

## План Проверки

1. Проверить prompt-only запуск:
   - один текстовый запрос достаточно запускает workflow;
   - агент сам находит состояние, каталог и первый артефакт;
   - пользователь не получает инструкцию вручную запускать `npm`.

2. Проверить ссылки:
   - в чате отображаются кликабельные абсолютные ссылки;
   - в сохраняемых файлах остаются только относительные пути;
   - для BMC — Business Model Canvas, бизнес-модели продукта, показаны Markdown, PlantUML, SVG, PNG, PDF и evidence, если файлы существуют.

3. Проверить редактирование:
   - ручной Markdown-источник можно изменить только после согласования;
   - generated artifacts — автоматически созданные файлы — нельзя изменить вручную;
   - после изменения источника генератор обновляет производные файлы.

4. Проверить разделение смыслов:
   - workflow не содержит правил поведения продукта DataCanvas;
   - продуктовые утверждения отображаются только как содержимое артефактов или предложенные правки;
   - любые продуктовые изменения требуют явного решения владельца.

5. Проверить валидацию:
   - профильный валидатор prompt-only workflow проходит;
   - `npm run generate:bmc -- --check` проходит для BMC — Business Model Canvas, бизнес-модели продукта;
   - `npm run validate:bmc` проходит;
   - `npm run generate:docs-navigation -- --check` проходит;
   - `npm run validate:doc-links` проходит;
   - `npm run validate:docs-navigation` проходит;
   - `npm run validate:artifact-registry` проходит;
   - `npm run validate:artifact-hashes` проходит;
   - полный `npm test` проходит перед handoff, если изменены общие контракты, схемы, навигация или generated artifacts — автоматически созданные файлы.

## Допущения

1. Пользователь хочет запускать процесс текстовым prompt — запросом в чате — без ручного ввода команд.
2. Агент имеет право запускать локальные команды генерации и проверки сам.
3. Абсолютные локальные ссылки нужны только в ответах чата для открытия файлов приложением по умолчанию.
4. Все сохраняемые документы, схемы и журналы должны использовать относительные пути.
5. Этот план является source of truth — источником истины — только для реализации workflow согласования и редактирования артефактов проектной документации.
