# RCA: исправление визуального выпуска прототипа Лисы

Навигация: [DataCanvas](../../README.md) / [Документация](../README.md) / [Выпуск](README.md) / RCA визуального выпуска CO-2026-003

## Проблема

Три финальных экрана статусов показывали один и тот же растр экрана формирования
презентации. Текст статуса добавлялся отдельной HTML/CSS-карточкой поверх растра.
Из-за этого на экране были одновременно видны исходный текст и новая карточка,
отличались шрифт, тень и композиция.

## Корневая причина

Договор пути определял статусы как виртуальные представления базового экрана
`7.2`, а генератор копировал его PNG-сегменты и добавлял `status_message` в
данные страницы. Проверки принимали наличие этой HTML-карточки как правильное
поведение. Реестр активных договоров перечислял десять состояний, тогда как
производные манифесты уже публиковали тринадцать; поэтому источник истины не
контролировал все экраны выпуска.

## Исправление

1. Реестр, договор пути, каталог рендеров, договор кадров и визуальная основа
   приведены к одному порядку из тринадцати состояний.
2. Для непринятия данных, задержки и частичной доставки добавлены отдельные
   канонические SVG-варианты исходного экрана `7.2`. Новая формулировка заменяет
   содержимое существующих групп строк; идентификаторы групп, стиль, цвет и
   прозрачный фон сохраняются. Текст сохраняется векторными контурами до
   растрирования; новый SVG-слой не добавляется.
3. Для каждого статусного экрана генератор выпускает собственные `system_top`,
   `scroll_content` и `system_bottom` PNG. Выпускная HTML-страница больше не
   создаёт карточку статуса поверх изображения.
4. Проверки требуют собственные ресурсы статусов, отсутствие HTML-наложения и
   сохранение статусных экранов только после успешной части пути.

## Предотвращение повторения

- Менять текст и его расположение на финальных статусных экранах можно только
  в существующих группах канонического SVG-источника. Нельзя добавлять SVG,
  HTML, CSS или PNG-слой поверх экрана. Сначала выполняется визуальная проверка
  SVG, затем штатный рендер PNG и генерация прототипа.
- При добавлении публичного состояния сначала обновляются единый реестр,
  договоры и проверки, затем производные HTML, PNG, архив и доказательства.
- В доказательства выпуска входят снимки каждого из тринадцати экранов в
  контрольных размерах; открытие PNG и успешный запуск сценария сами по себе
  не являются визуальной приёмкой.
- SHA-256 SVG в каталоге рендеров синхронизируется штатным обновителем исходников
  и проверяется профильным набором; расхождение блокирует выпуск до рендеринга.
- Манифест снимков хранит относительный путь и отпечаток кандидата по значению
  SHA-256. Генератор не сравнивает два разных объекта JSON как ссылки в памяти,
  а проверяет алгоритм и строку хэша.

## Дополнительные причины, обнаруженные при исправлении

1. Каталог рендеров всё ещё содержал прежний SHA-256 исходника `7.2`, хотя
   импорт растров использовал обновлённый SVG. Причина — обновитель SVG не
   синхронизировал каталог происхождения, а его проверка не входила в
   профильный набор. Исправление: штатный обновитель пересчитывает SHA-256
   всех зарегистрированных локальных источников; профильный набор запускает
   проверку происхождения.
2. Первый вариант генератора снимков записывал файлы в двойной каталог
   `screenshots/screenshots`, а манифест указывал на одиночный. Причина — путь
   формировался относительно каталога назначения, но уже содержал его имя.
   Исправление: снимки создаются во временном дереве, содержащем только
   `webkit/**`, а затем одним переносом заменяют прежний каталог.
3. Проверка свежести снимков сравнивала два объекта JSON по ссылке, из-за чего
   корректный манифест мог быть ошибочно признан устаревшим. Причина — вместо
   сравнения структуры отпечатка использовалось сравнение объектов. Исправление:
   сравниваются `algorithm` и `sha256`; регрессионная проверка требует совпадения
   отпечатка снимков с манифестом прототипа.
4. Обработчик переменного шрифта мог выдавать `NaN` в координатах некоторых
   кириллических слов при построении контура сразу в конечной позиции. Причина —
   дефект вычисления абсолютных координат в используемой библиотеке шрифтов.
   Исправление: контуры строятся в локальном начале координат и переносятся
   атрибутом `transform`; при `NaN` слово безопасно разбивается на глифы. Любой
   `NaN` блокирует запись SVG и последующий рендер.
