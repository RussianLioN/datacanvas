# Формализованные Пользовательские Истории v0.2

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Продукт](../README.md) / [Требования](README.md) / Пользовательские истории

## Назначение

Документ фиксирует формализованный слой пользовательских историй DataCanvas на основе канонического каталога [Stories](../../stories.md). `DC-ST-*` — пользовательские истории DataCanvas — остаются первичными стабильными идентификаторами для требований, backlog — продуктового списка работ, roadmap — дорожной карты, traceability — трассировки и sprint planning — планирования спринтов.

Предыдущие `US-*` — старые пользовательские истории — удалены из активного продуктового слоя, потому что они не совпадали с текущим каталогом `DC-ST-*` — пользовательских историй DataCanvas — и смешивали продуктовый и процессный контуры.

## Правила Использования

- `docs/stories.md` остается каноническим story catalog — каталогом пользовательских историй.
- Этот документ является формализованным ручным продуктовым источником для требований и планирования.
- `DC-ST-23..DC-ST-29` — пользовательские истории запуска DataCanvas другим агентом и подготовки результата — подтверждены Product Owner как P1-истории.
- Оценки для `DC-ST-23..DC-ST-29` — пользовательских историй запуска DataCanvas другим агентом и подготовки результата — должны быть подтверждены командой реализации до планирования спринта.
- Нельзя создавать новые `BT-*` — бизнес-требования — или `PBI-*` — элементы продуктового бэклога — из этих историй без отдельного решения Product Owner.
- Плановые даты остаются ориентирами, а не обещанными релизами.

- `UDW-DEC-018` — решение Product Owner по `DC-ST-29` — пользовательской истории генерации файла презентации: закрыто; история добавлена без создания нового `BT-*` — бизнес-требования.

- Оценка, емкость и ресурсы для `DC-ST-23..DC-ST-29` — пользовательских историй запуска DataCanvas другим агентом и подготовки результата — должны быть подтверждены командой реализации до превращения candidate plan — кандидатного плана — в sprint backlog — список работ спринта.
