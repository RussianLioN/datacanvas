# Каталог пользовательских историй DataCanvas

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Продукт](../README.md) / [Требования](README.md) / Пользовательские истории

## Назначение

Документ содержит канонический перечень пользовательских историй DataCanvas. Он используется для продуктового обсуждения, уточнения требований и планирования работ.

## Каталог пользовательских историй

В каталог включены только истории, входящие в границу реализации 2026 года. Они опираются на [границу реализации 2026 года](../sources/co-2026-003-current-2026-scope.md), [стенограмму интервью](../change-orders/co-2026-003-q4-lisa-profile-bt-interview-transcript.md) и принятые бизнес-требования. Условия одного заказа, сохранения состояния и обработки задержки включены в соответствующие базовые истории, а не вынесены в отдельные дублирующие пункты.

| ID | Функциональная зона | Приоритет | Пользовательская формулировка | Бизнес-ценность |
|---|---|---|---|---|
| DC-ST-09 | Получение результата | P2 | Как пользователь, я хочу получить готовую презентацию по электронной почте, чтобы использовать её в работе. | Это позволит использовать готовую презентацию в рабочем процессе без ручной передачи файла. |
| DC-ST-23 | Заказ из Лисы | P1 | Как пользователь Лисы, я хочу создать один заказ на подготовку презентации из полной справки о клиенте, чтобы начать подготовку без переноса данных в другой чат. | Это позволит начать подготовку презентации из полной справки о клиенте, исключая дублирование заказа в одном сеансе. |
| DC-ST-24 | Запуск в общем сценарии | P1 | Как вызывающий агент, я хочу передать DataCanvas заказ из уже собранного контекста, чтобы подготовка презентации началась без повторного ввода данных. | Это позволит включить подготовку презентации в общий сценарий без повторного ввода уже собранных данных. |
| DC-ST-25 | Определение адресов | P1 | Как пользователь Лисы, я хочу, чтобы адреса получателей определялись только через «Профиль сотрудника», чтобы результат не направлялся на произвольный адрес. | Это снижает риск ошибочной доставки и исключает произвольные адреса в запросе. |
| DC-ST-26 | Проверка заказа | P1 | Как пользователь Лисы или вызывающий агент, я хочу получить безопасный результат проверки заказа до начала подготовки, чтобы неполные или неразрешённые заказы не запускались. | Это предотвращает запуск по неполным, небезопасным или неразрешённым данным. |
| DC-ST-27 | Статусы заказа | P1 | Как пользователь Лисы, я хочу видеть в том же чате сообщения о принятии, начале подготовки, успехе, задержке, частичной доставке или непринятом заказе, чтобы понимать состояние без потери контекста. | Это позволяет видеть текущее состояние заказа в рабочем контексте и возвращаться к нему без потери сведений. |
| DC-ST-28 | Проверяемость маршрута | P1 | Как сотрудник сопровождения, я хочу проследить связь заказа, результата проверки, статусов и итоговых файлов, чтобы разбирать обращения и подтверждать ход обработки. | Это позволяет разбирать обращения и подтверждать путь обработки каждого заказа. |
| DC-ST-29 | Подготовка результата | P1 | Как пользователь, я хочу получить подготовленные из проверенных данных PPTX и PDF, чтобы использовать редактируемую версию и версию для просмотра. | Это позволяет использовать редактируемую версию и версию для просмотра без ручной подготовки файлов. |
| DC-ST-30 | Почтовая доставка | P2 | Как пользователь Лисы, я хочу получать по электронной почте PPTX и PDF в разрешённых контурах, а при задержке или частичной доставке — достоверный итог, чтобы использовать результат или передать вопрос в сопровождение. | Это позволяет получить результат в разрешённых контурах или своевременно передать вопрос в сопровождение. |
