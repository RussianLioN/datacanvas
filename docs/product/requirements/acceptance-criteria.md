# Критерии приемки v0.2

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Продукт](../README.md) / Критерии приемки

## Назначение

Документ фиксирует условия, при которых продуктовый результат DataCanvas можно считать принятым. Проверочные доказательства, журналы выполнения и служебные статусы ведутся во внешнем проверочном контуре.

## Критерии приемки

Q4_2026 трассируется к `CO3-DEC-001`–`CO3-DEC-009` и историческим `CO3-MSG-001`–`CO3-MSG-005` [реестра интервью](../change-orders/co-2026-003-authoritative-interview-decision-register.md). Для будущего кандидата подпись кнопки, сообщения начала и успеха, тема и тело письма принимаются только при дословном совпадении с [реестром утверждённых текстов](../analysis/presentation-link-lisa-user-journey/owner-approved-texts.md).

### Базовая приемка

- Входной пакет проверяется на достаточность и допустимость.
- Нормализованные данные сохраняют ссылки на источники.
- Недостаточный вход останавливает подготовку презентации; уточняющие вопросы задаются в Лисе, если сценарий идет в диалоговом режиме.
- При запуске другим агентом DataCanvas после проверки достаточности и безопасности данных сообщает вызывающему агенту о приеме данных, готовит презентацию без пользовательского подтверждения и отправляет пользователю редактируемый `PPTX`-файл и нередактируемую `PDF`-копию по электронной почте.
- В диалоговом режиме в Лисе DataCanvas показывает описание структуры, после чего пользователь выбирает: изготовить презентацию или перейти к редактированию структуры.
- DataCanvas формирует редактируемый `PPTX`-файл презентации и нередактируемую `PDF`-копию из проверенных и нормализованных данных до запуска доставки.
- Каждое значимое утверждение в результате связано с источником.
- Итоговый файл и почтовая доставка не раскрывают лишние служебные или конфиденциальные данные.
- В контуре `Q4_2026` адреса определяются только через «Профиль сотрудника», а результат в `ODT` и `PDF` отправляется по электронной почте.
- В контуре `Q4_2026` для пары сеанс/пользователь принимается один заказ; после принятия новый заказ не создается, а безопасное состояние остается в том же чате Лисы.

### Сценарии приемки по маршрутам

| Сценарий | Связанные BT | Ожидаемый результат | Условие приемки |
|---|---|---|---|
| Запуск другим агентом | `BT-015`, `BT-016`, `BT-017`, `BT-006`, `BT-012`, `BT-014`, `BT-018` | DataCanvas принимает запрос от другого агента, получает входной пакет с данными для определения получателя результата, проверяет достаточность и безопасность данных, сообщает вызывающему агенту о приеме данных, готовит презентацию без пользовательского подтверждения, отправляет пользователю редактируемый `PPTX`-файл и нередактируемую `PDF`-копию по электронной почте и формирует статусы для вызывающего агента | Путь от запроса другого агента до доставленных файлов проверяем и не смешивается с маршрутом Лисы. |
| Диалоговый режим в Лисе | `BT-005`, `BT-007`, `BT-008`, `BT-009`, `BT-010`, `BT-012`, `BT-014` | Пользователь видит описание структуры и выбирает: изготовить презентацию или перейти к редактированию структуры; после выбора изготовления файл отправляется по электронной почте | Пользователь явно управляет действием после просмотра структуры. |
| Недостаточный входной контекст | `BT-006`, `BT-007` | Недостаточные данные не приводят к изготовлению презентации; в Лисе DataCanvas задает уточняющие вопросы | Неполный контекст не приводит к готовому файлу без уточнения. |
| Прием запроса от другого агента | `BT-015`, `BT-014` | DataCanvas принимает запрос от другого агента без участия Лисы и связывает его с дальнейшей проверкой входного пакета | Запрос другого агента отличим от запуска через Лису. |
| Входной пакет от другого агента | `BT-016`, `BT-017`, `BT-006`, `BT-013` | Неполный, небезопасный или инструктивный вход от другого агента не запускает генерацию; вход без данных для определения получателя результата не переходит к доставке | DataCanvas продолжает работу только после достаточного и безопасного входа. |
| Генерация файлов презентации | `BT-012`, `BT-002`, `BT-014` | DataCanvas формирует редактируемый `PPTX`-файл презентации и нередактируемую `PDF`-копию из проверенных и нормализованных данных до отправки пользователю | Пользователь получает рабочий результат без ручной сборки презентации. |
| Статусы для вызывающего агента | `BT-018`, `BT-014` | DataCanvas сообщает о приеме данных после успешной проверки, формирует статусы обработки и сведения о результате для вызывающего агента | Вызывающий агент понимает, принят ли запрос, остановлен ли вход и завершилась ли подготовка результата. |
| Проверяемость двух маршрутов | `BT-014`, `BT-015`, `BT-016`, `BT-017`, `BT-018`, `BT-012` | DataCanvas сохраняет проверяемую связь маршрута запуска другим агентом и маршрута Лисы без смешивания шагов | Для каждого результата можно восстановить, каким маршрутом он был подготовлен. |
| Правка до генерации | `BT-010` | Пользователь в Лисе дополняет, перемещает или удаляет блоки до генерации | Правки выполняются до изготовления презентации. |
| Выбор формата и шаблона | `BT-011` | КМ выбирает формат и шаблон из предложенных вариантов | Выбранный вариант понятен пользователю до генерации. |
| Доставка по электронной почте | `BT-012`, `BT-014` | Редактируемый `PPTX`-файл и нередактируемая `PDF`-копия отправлены по электронной почте, статус доставки зафиксирован | Пользователь получает рабочий результат по подтвержденному каналу. |
| Расширенная электронная доставка | `BT-019`, `BT-014` | Созданные файлы отправлены в разрешенные рабочие контуры через электронный канал | Пользователь получает результат в согласованном рабочем контуре без ручной пересылки. |
| Хранение нередактируемой копии | `BT-020`, `BT-014` | Нередактируемая `PDF`-копия сохранена в защищенном хранилище и связана с подготовленным результатом | Ссылку можно использовать для открытия готовой копии без повторной отправки файла. |
| Передача ссылки вызывающему агенту | `BT-020`, `BT-018` | Вызывающий агент получает ссылку на нередактируемую `PDF`-копию после подготовки результата | Вызывающий агент и Лиса могут показать пользователю готовую ссылку в рабочем сценарии. |
| Уведомление в Лисе | `BT-021`, `BT-020` | Пользователь получает в Лисе ссылку на готовую презентацию и уведомление о готовности через сценарий вызывающего агента и Лисы | Уведомление не смешивается с доставкой по электронной почте в основном маршруте и согласуется с командами этого сценария. |
| Заказ из Лисы в Q4_2026 | `BT-015`, `BT-017`, `BT-022` | Допустимый запрос с полной справки Лисы через утверждённую подпись кнопки сразу создает один заказ для пары сеанс/пользователь; непринятый запрос можно исправить | После принятия новый заказ для той же пары отклоняется, а после успеха действие недоступно до завершения сеанса; подпись кнопки совпадает с реестром утверждённых текстов. |
| Адреса и почтовая доставка Q4_2026 | `BT-016`, `BT-019` | Адреса получены только через «Профиль сотрудника»; `ODT` и `PDF` отправлены по одному или двум допустимым контурам | Отсутствие или недоступность адреса не считается принятым заказом; произвольный адрес из запроса не используется. |
| Состояние в том же чате | `BT-018`, `BT-023` | Пользователь видит в том же чате Лисы безопасные сообщения о начале, успехе, задержке, частичной доставке или непринятом запросе | При возвращении в чат состояние остается доступным без системного PUSH и без отдельной ссылки на файл; тексты начала и успеха совпадают с реестром утверждённых текстов. |
| Тема и тело письма Q4_2026 | `BT-019` | Письмо с `ODT` и `PDF` содержит утверждённые тему и тело | Тема и тело письма дословно совпадают с реестром утверждённых текстов; почтовый технический договор при этом не изобретается. |
| Задержанная или частичная доставка | `BT-019`, `BT-024` | После задержанной, частичной или неуспешной доставки пользователь видит безопасное сообщение, а сеанс закрывается | Дальнейшее сопровождение передано внешнему контуру; число повторов и канал сопровождения не определены этим критерием. |
| Неподтвержденное утверждение | `BT-003`, `BT-013` | Неподтвержденное утверждение уточняется или исключается | Финальный результат не содержит утверждений без источника. |
| Конфликтующие источники | `BT-003`, `BT-014` | Конфликтующие данные не становятся финальным утверждением без разрешения | DataCanvas уточняет конфликт, исключает спорный фрагмент или использует выбранный владельцем источник. |
| Недоверенные инструкции во входе | `BT-006`, `BT-017`, `BT-013` | Инструкции из входного текста, ответа агента или вложений не меняют правила DataCanvas | DataCanvas обрабатывает вход как данные, а не как новые правила системы. |
| Утечка конфиденциальных данных | `BT-004`, `BT-013` | Конфиденциальные данные не попадают в готовый файл или почтовую доставку сверх разрешенного состава | При риске раскрытия лишних данных подготовка или отправка останавливается. |

## Открытые вопросы

- Редактируемый `PPTX`-файл презентации и нередактируемая `PDF`-копия остаются историческим результатом маршрута запуска другим агентом. Для `Q4_2026` принятым результатом являются `ODT` и `PDF`.
- Рабочая почта пользователя рассматривается как продуктовое решение для основного маршрута; правила адресата и подтверждения доставки уточняются в системном анализе.
- `DC-ST-03/04` проходят приемку по действию с описанием презентации; ценность состоит в улучшении структуры презентации до генерации файла.
- Системный PUSH, отдельное хранилище и ссылка на нередактируемую `PDF`-копию относятся к будущему объему за пределами `Q4_2026` и требуют отдельной приемки.
