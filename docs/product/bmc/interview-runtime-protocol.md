# Протокол Живого BMC-Интервью

Статус: `draft_runtime_ready`

Этот протокол описывает живое BMC-интервью DataCanvas в Codex-чате. Пользователь отвечает обычным текстом. JSON остается внутренним форматом сохранения, проверки и генерации артефактов.

## Цель

Провести BMC-брейншторм по одному вопросу за раз, динамически выбирая следующий вопрос по текущему состоянию интервью.

## Старт

Интервью начинается с выбора:

- времени: 15, 30, 60 или 90 минут;
- глубины: быстро, стандартно или глубоко;
- цели: первичный BMC, уточнение BMC, проверка гипотез или подготовка к roadmap.

Если пользователь не выбирает явно, используются значения по умолчанию: 60 минут, стандартная глубина, первичный BMC.

## Шаг Интервью

Каждый пользовательский шаг должен содержать:

- номер шага;
- BMC-блок;
- один вопрос;
- 3-6 вариантов ответа;
- вариант "свой вариант";
- вариант "не знаю / пропустить";
- короткий запрос подтверждения, если ответ влияет на утверждение BMC.

Агент не задает несколько смысловых вопросов одновременно.

## Русский Язык

Все вопросы, варианты ответов, подсказки и резюме для пользователя должны быть написаны естественным русским языком.

Запрещено использовать англоязычные служебные слова в пользовательском тексте, если есть нормальная русская замена:

- вместо `review` писать `проверка`;
- вместо `export` писать `выдача результата` или `выгрузка`, если речь именно о файле;
- вместо `claim` писать `утверждение`;
- вместо `evidence` писать `подтверждение`;
- вместо `custom answer` писать `свой ответ`;
- вместо `skip` писать `пропустить`;
- вместо `unknown` писать `не знаю`;
- вместо `source trace` писать `трассировка к источникам`;
- вместо `templates` писать `шаблоны`;
- вместо `router` писать `маршрутизатор вопросов`, если это видит пользователь.

Английский допустим только для имен продуктов, протоколов, команд, файлов, путей, форматов и общепринятых аббревиатур: DataCanvas, Codex, BMC, JSON, A2A, MCP, LLM, API, CSM, UAT. При первом употреблении рядом должно быть русское пояснение, если термин может быть непонятен пользователю.

## Состояние

После каждого ответа обновляется runtime-state:

- выбранный режим;
- текущий шаг;
- покрытые BMC-блоки;
- заданные вопросы;
- ответы;
- подтверждения;
- отметки об отсутствующих подтверждениях;
- решения маршрутизации вопросов;
- снимок утверждений;
- открытые вопросы.

Статусы состояния:

- `not_started`;
- `in_progress`;
- `paused`;
- `ready_for_confirmation`;
- `completed`;
- `abandoned`.

## Выбор Следующего Вопроса

LLM-маршрутизатор выбирает следующий вопрос по состоянию:

- непокрытые BMC-блоки имеют приоритет;
- низкая уверенность ведет к уточнению;
- свой ответ ведет к нормализации формулировки;
- "не знаю" или "пропустить" ведет к гипотезам или переходу дальше при коротком режиме;
- отсутствие подтверждения создает отметку об отсутствующем подтверждении;
- противоречие ведет к разрешению противоречия;
- глубокий режим включает экономику, альтернативы, риски и план проверки.

## Подтверждения

Пользовательский ответ не считается подтверждением сам по себе.

Если подтверждение не предоставлено:

- утверждение сохраняется;
- утверждение получает статус `unconfirmed` или `assumption`;
- создается отметка об отсутствующем подтверждении;
- итоговый артефакт содержит запрос подтверждения.

Если подтверждение предоставлено, сохраняются только безопасные метаданные, отредактированная цитата или контролируемая ссылка.

## Пауза И Продолжение

Сессия может быть продолжена из active runtime-state. При продолжении агент показывает:

- что уже покрыто;
- какой вопрос следующий;
- какие подтверждения отсутствуют.

## Завершение

Перед финальной записью агент показывает резюме:

- подтвержденные утверждения;
- неподтвержденные утверждения;
- допущения;
- противоречивые утверждения;
- ключевые гипотезы;
- отсутствующие подтверждения;
- открытые вопросы.

Финальные BMC-артефакты обновляются только после подтверждения пользователя.
