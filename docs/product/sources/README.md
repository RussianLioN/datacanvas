# Исходные Документы Продукта DataCanvas

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Продукт](../README.md) / Исходные документы

Статус: draft
Владелец: Product Owner
Проверка: `npm run validate:product-sources`, `npm run validate:xlsx-backlog`, `npm run validate:xlsx-cascade`

## Назначение

Этот раздел показывает, какие документы считаются исходными для продуктового смысла DataCanvas, а какие являются производными, историческими или проверочными.

Если документы расходятся, решение принимается по актуальному источнику с более высоким приоритетом, а не по generated artifacts, старым evidence или техническим схемам.

## Текущий Порядок Доверия

1. Текущее видение продукта.
2. Принятые решения Product Owner и accepted `CO-*` - утвержденные заявки на продуктовые изменения.
3. Принятые решения владельца продукта, граница реализации 2026 года и бизнес-требования.
4. Требования, критерии приемки и трассировка — после их отдельного последовательного обновления.
5. BA/SA analysis - бизнес-анализ и системный анализ - и specs - спецификации.
6. Evidence - доказательства, журналы, generated artifacts - автоматически созданные артефакты - и исторические snapshots - снимки.

Для границы и приоритетов реализации 2026 года первым прикладным источником
является [граница реализации 2026 года](co-2026-003-current-2026-scope.md),
подготовленная по актуальной очищенной книге владельца продукта и полной
безопасной стенограмме интервью. Ресурсные данные не входят в эту границу.

## Машинный Реестр

Машинно-проверяемый реестр находится в [`product-source-registry.json`](product-source-registry.json).

Он фиксирует `source_id`, владельца, жизненный цикл, статус доверия, допустимое использование и связанные документы.

## Рабочие Excel-Версии

Рабочие Excel-версии хранятся в `docs/product/sources/working/` и учитываются
через машинный реестр. Для текущего каскада используется только явно выделенная
владельцем продукта выборка историй первого листа книги от 19 августа 2026 года;
ресурсные значения не используются. Перенос в спринтовое планирование требует
отдельного решения и не является следствием принятия бизнес-требований.

- [Актуальная очищенная книга 2026 года](working/datacanvas-backlog-draft-pshe-2026-08-19.xlsx) — источник границы и приоритетов девяти действующих историй 2026 года. Ее ресурсные данные и остальные листы не используются для бизнес-требований.
- [Граница реализации 2026 года](co-2026-003-current-2026-scope.md) — человекочитаемый перечень действующих историй и исключений.
- [Полная безопасная стенограмма интервью](../change-orders/co-2026-003-q4-lisa-profile-bt-interview-transcript.md) — дополнительный источник бизнес-смысла для кандидата требований.


## Индексы Восстановления И Экспорта

- `docs/product/sources/xlsx-opml-jira-recovery-index.json` - машинный индекс текущего состояния цепочки `XLSX -> OPML -> Jira import`: безопасные внешние метаданные исторического OPML, подготовленный пакет ручного импорта Jira и связанные файлы комплекта для Confluence. Внешний SHA-256 OPML хранится как контрольный отпечаток и не считается локально проверенным источником.

## Проверка Excel-Оценок

Рабочие Excel-версии backlog проверяются командой:

```bash
npm run validate:xlsx-backlog
npm run validate:xlsx-cascade
```

Проверки сверяют контролируемый и рабочий XLSX, манифест происхождения и эталон допустимых изменений; отдельно подтверждают отсутствие локальных путей во всей истории кандидата и полноту каскадного графа. Эти проверки обязательны перед переносом принятых оценок ПШЕ в планирование спринта.

## Принятый Контур Бизнес-Требований

[Бизнес-требования 2026 года](../requirements/business-requirements.md) приняты на
основании границы реализации и стенограммы интервью. Следующий отдельный этап —
оформление пользовательских историй; до него старые материалы не являются
маршрутом текущей продуктовой документации.
