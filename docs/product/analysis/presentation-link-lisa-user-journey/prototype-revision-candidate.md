# Кандидат пересборки прототипа CO-2026-003

Навигация: [DataCanvas](../../../../README.md) / [Документация](../../../README.md) / [Продукт](../../README.md) / [Аналитика](../README.md) / [Пользовательский путь заказа презентации в Лисе](README.md) / Кандидат пересборки прототипа CO-2026-003

`CO-2026-003` — изменение Q4_2026 для заказа презентации из агента «Справка по клиенту» в Лисе. Этот документ фиксирует фундамент будущей пересборки прототипа после утверждения формулировок и получения трёх PDF-доноров вариантов презентации. Он не активирует новый визуальный контур, не меняет текущий `journey-contract.json` и не разрешает рендер новых кадров.

## Что зафиксировано

Машиночитаемый кандидат находится в [source/prototype-revision-candidate.json](source/prototype-revision-candidate.json). Он задаёт будущий активный набор из 11 кадров: полная справка, начало формирования, список чатов, успешная отправка, письмо, три варианта презентации и три ошибочных экрана в конце галереи. Старые кадры `lisa-materials-summary` — краткая справка и `lisa-presentation-order` — отдельный экран заказа сохранены как исторические и не входят в будущий активный маршрут. Кандидат не включён в активный реестр договоров и не является входом действующего генератора.

Очищенная модель клиента находится в [source/client-reference-data.json](source/client-reference-data.json). В ней отражены данные по ООО «Водолей Трейд»: общая информация, собственник, финансовые показатели, сотрудничество, доля в Сбере, сделки, потенциал, предодобренные предложения, инсайты, договорённости, динамические подсказки и действия. Исходный документ, локальный путь, хэш, авторские свойства и временные производные файлы в репозиторий не сохраняются.

При первой поэкранной правке полной справки эти очищенные данные заменят данные ГК Достовалова внутри существующих групп канонического SVG. Экран начала формирования и другие продолжения будут обновляться только после того, как данные полной справки и её SVG-кадр согласованы.

Договор брейншторма находится в [source/brainstorming-contract.json](source/brainstorming-contract.json). В нём ровно пять независимых тем: текст кнопки, сообщение о начале формирования, сообщение об успешной отправке, тема письма и тело письма. Исторические результаты двухфазного обсуждения сохранены отдельно. Владелец продукта утвердил итоговые формулировки; их единственный источник истины — [реестр утверждённых текстов](owner-approved-texts.md).

## Два разных порядка

Семантический порядок описывает сценарий: полная справка ведёт к проверке данных; если данные не приняты, показывается ошибка и пользователь возвращается к полной справке; если данные приняты, начинается формирование, затем возможны успех, задержка или частичная доставка. Отдельные рёбра просмотра после успеха описывают выход в список чатов, возврат в тот же чат, открытие письма и просмотр каждого варианта презентации с возвратом к письму. Эти рёбра не делают ошибочные экраны частью успешного просмотра.

Порядок галереи нужен для демонстрации стейкхолдерам: сначала весь успешный путь, затем три ошибки. Этот порядок не является переходом пользователя по сценарию.

## Блокировка визуального выпуска

Новые SVG, PNG, HTML и архив нельзя выпускать, пока не выполнены все условия:

- три PDF-донора вариантов презентации зарегистрированы; они не являются прямым входом рендера;
- для каждого из трёх вариантов презентации подготовлен канонический SVG кадрового изображения до любого чернового, HTML или высокого рендера;
- получен редактируемый канонический SVG-исходник кадра письма, потому что текущий кадр письма хранится как PNG;
- каждый кадр прошёл цикл: согласование текста, правка существующей группы в каноническом SVG с сохранением стиля, визуальная сверка SVG, черновой PNG в текущем разрешении в изолированной копии текущего прототипа, явное согласование владельца; в такой копии одновременно заменяется только один одноимённый кадр;
- после всех кадров согласован полный черновой прототип в текущем разрешении;
- только после этого высокий рендер выполняется заново из согласованных SVG-исходников.

Запрещены наложения текста через HTML, CSS, PNG или дополнительный SVG, а также масштабирование чернового PNG для финального выпуска. Наличие PDF-донора презентации не разрешает рендер: сначала нужен канонический SVG соответствующего кадра.
