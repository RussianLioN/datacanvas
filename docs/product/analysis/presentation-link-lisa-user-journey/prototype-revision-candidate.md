# Кандидат пересборки прототипа CO-2026-003

Навигация: [DataCanvas](../../../../README.md) / [Документация](../../../README.md) / [Продукт](../../README.md) / [Аналитика](../README.md) / [Пользовательский путь заказа презентации в Лисе](README.md) / Кандидат пересборки прототипа CO-2026-003

`CO-2026-003` — изменение Q4_2026 для заказа презентации из агента «Справка по клиенту» в Лисе. Этот документ фиксирует фундамент будущей пересборки прототипа после брейншторма формулировок и получения редактируемых исходников. Он не активирует новый визуальный контур, не меняет текущий `journey-contract.json` и не разрешает рендер новых кадров.

## Что зафиксировано

Машиночитаемый кандидат находится в [source/prototype-revision-candidate.json](source/prototype-revision-candidate.json). Он задаёт будущий активный набор из 11 кадров: полная справка, начало формирования, список чатов, успешная отправка, письмо, три варианта презентации и три ошибочных экрана в конце галереи. Старые кадры `lisa-materials-summary` — краткая справка и `lisa-presentation-order` — отдельный экран заказа сохранены как исторические и не входят в будущий активный маршрут.

Очищенная модель клиента находится в [source/client-reference-data.json](source/client-reference-data.json). В ней отражены данные по ООО «Водолей Трейд»: общая информация, собственник, финансовые показатели, сотрудничество, доля в Сбере, сделки, потенциал, предодобренные предложения, инсайты, договорённости, динамические подсказки и действия. Исходный документ, локальный путь, хэш, авторские свойства и временные производные файлы в репозиторий не сохраняются.

Договор брейншторма находится в [source/brainstorming-contract.json](source/brainstorming-contract.json). В нём ровно пять независимых тем: текст кнопки, сообщение о начале формирования, сообщение об успешной отправке, тема письма и тело письма. По каждой теме сначала владелец продукта даёт вводные, затем первая группа из 19 участников с общим контекстом готовит 30 разных кандидатов, вторая независимая группа из 19 участников выбирает 5 кандидатов, после чего владелец продукта явно выбирает итоговый текст.

## Два разных порядка

Семантический порядок описывает сценарий: полная справка ведёт к проверке данных; если данные не приняты, показывается ошибка и пользователь возвращается к полной справке; если данные приняты, начинается формирование, затем возможны успех, задержка или частичная доставка.

Порядок галереи нужен для демонстрации стейкхолдерам: сначала весь успешный путь, затем три ошибки. Этот порядок не является переходом пользователя по сценарию.

## Блокировка визуального выпуска

Новые SVG, PNG, HTML и архив нельзя выпускать, пока не выполнены все условия:

- владелец продукта выбрал итоговые формулировки по пяти темам;
- получены три актуальных редактируемых исходника вариантов презентации;
- получен редактируемый канонический SVG-исходник кадра письма, потому что текущий кадр письма хранится как PNG;
- каждый кадр прошёл цикл: согласование текста, правка существующей группы в каноническом SVG с сохранением стиля, визуальная сверка SVG, черновой PNG в текущем разрешении, явное согласование владельца;
- после всех кадров согласован полный черновой прототип в текущем разрешении;
- только после этого высокий рендер выполняется заново из согласованных SVG-исходников.

Запрещены наложения текста через HTML, CSS, PNG или дополнительный SVG, а также масштабирование чернового PNG для финального выпуска.
