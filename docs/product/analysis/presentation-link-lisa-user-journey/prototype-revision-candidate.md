# Кандидат пересборки прототипа CO-2026-003

Навигация: [DataCanvas](../../../../README.md) / [Документация](../../../README.md) / [Продукт](../../README.md) / [Аналитика](../README.md) / [Пользовательский путь заказа презентации в Лисе](README.md) / Кандидат пересборки прототипа CO-2026-003

`CO-2026-003` — изменение Q4_2026 для заказа презентации из агента «Справка по клиенту» в Лисе. Этот документ фиксирует принятый изолированный черновик после утверждения формулировок и получения трёх PDF-доноров вариантов презентации. Он не изменяет действующие визуальные артефакты и не разрешает чистовой рендер, доказательства или архив.

## Что зафиксировано

Машиночитаемый кандидат находится в [source/prototype-revision-candidate.json](source/prototype-revision-candidate.json), а факт принятия — в [манифесте изолированного черновика](candidate-evidence/prototype-draft/manifest.json). Вместе они задают 11 кадров: полная справка, начало формирования, список чатов, успешная отправка, письмо, три варианта презентации и три ошибочных экрана в конце галереи. Старые кадры `lisa-materials-summary` — краткая справка и `lisa-presentation-order` — отдельный экран заказа сохранены как исторические и не входят в новый маршрут. Кандидат не включён в активный реестр договоров и не является входом действующего генератора.

Очищенная модель клиента находится в [source/client-reference-data.json](source/client-reference-data.json). В ней отражены данные по ООО «Водолей Трейд»: общая информация, собственник, финансовые показатели, сотрудничество, доля в Сбере, сделки, потенциал, предодобренные предложения, инсайты, договорённости, динамические подсказки и действия. Исходный документ, локальный путь, хэш, авторские свойства и временные производные файлы в репозиторий не сохраняются.

Очищенные данные уже заменили данные ГК Достовалова внутри существующих групп канонического SVG изолированного черновика. Экран начала формирования и последующие продолжения сохранены как согласованные продолжения полной справки.

Договор брейншторма находится в [source/brainstorming-contract.json](source/brainstorming-contract.json). В нём ровно пять независимых тем: текст кнопки, сообщение о начале формирования, сообщение об успешной отправке, тема письма и тело письма. Исторические результаты двухфазного обсуждения сохранены отдельно. Владелец продукта утвердил итоговые формулировки; их единственный источник истины — [реестр утверждённых текстов](owner-approved-texts.md).

## Два разных порядка

Семантический порядок описывает сценарий: полная справка ведёт к проверке данных; если данные не приняты, показывается ошибка и пользователь возвращается к полной справке; если данные приняты, начинается формирование, затем возможны успех, задержка или частичная доставка. Отдельные рёбра просмотра после успеха описывают выход в список чатов, возврат в тот же чат, открытие письма и просмотр каждого варианта презентации с возвратом к письму. Эти рёбра не делают ошибочные экраны частью успешного просмотра.

Порядок галереи нужен для демонстрации стейкхолдерам: сначала весь успешный путь, затем три ошибки. Этот порядок не является переходом пользователя по сценарию.

## Граница после принятия черновика

Изолированный черновик принят, но чистовой выпуск нельзя выполнять, пока не завершены все условия:

- три PDF вариантов презентации зарегистрированы и использованы только штатным контролируемым импортёром для изолированных PNG-черновиков;
- каждый из трёх вариантов презентации принят в составе изолированного черновика непосредственно из соответствующего PDF без пересборки текста, таблиц, диаграмм и макета;
- кадр письма подготовлен самостоятельной SVG-композицией по предоставленному визуальному образцу Outlook и принят владельцем; исходный снимок не хранится в репозитории;
- каждый мобильный кадр и письмо прошли цикл: согласование текста, правка существующей группы в каноническом SVG с сохранением стиля, визуальная сверка SVG, черновой PNG в текущем разрешении и явное согласование владельца; три презентационных кадра получены из соответствующих PDF без пересборки макета; по предварительному разрешению владельца их можно одновременно показать только в изолированной копии прежнего прототипа с тем же оформлением, навигацией и размерами сцен: телефон `393×852` с трёхкратной плотностью слоёв, письмо `1553×1013`, презентация `960×540`; принимать необходимо каждый отдельно;
- полный черновой прототип в текущем разрешении принят только для документального каскада;
- завершён документальный каскад и Владелец отдельно подтвердил переход к чистовому выпуску;
- только после этого высокий рендер выполняется заново из согласованных исходников: SVG для мобильных кадров и PDF для трёх вариантов презентации.

Запрещены наложения текста через HTML, CSS, PNG или дополнительный SVG, а также масштабирование чернового PNG для финального выпуска. Для мобильных кадров Лисы и письма обязателен канонический SVG. Для трёх вариантов презентации обязательны исходный PDF с зафиксированным хэшем, штатное контролируемое преобразование в PNG и отдельная приёмка каждого варианта; новый SVG для них не создаётся.
