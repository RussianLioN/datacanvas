# Пользовательский путь заказа и получения презентации в Лисе

Навигация: [DataCanvas](../../../../README.md) / [Документация](../../../README.md) / [Продукт](../../README.md) / [Аналитика](../README.md) / Пользовательский путь заказа и получения презентации в Лисе

Статус прототипа: подтверждён владельцем (`owner-approved-prototype`).

## Назначение

Пакет описывает и показывает путь пользователя от нажатия кнопки «Заказать презентацию» в диалоге Лисы до просмотра нередактируемой `PDF`-копии, возврата в чат и отправки `PDF`- и `PPTX`-файлов по электронной почте.

Это документальный и проверочный пакет для будущей группы возможностей `P2` — доставки результата по ссылке. Он не является промышленной реализацией Лисы, DataCanvas, защищённого хранилища или почтовой доставки и не изменяет канонические требования.

Все сведения о людях и организациях в демонстрации синтетические.

## Прямое открытие состояний

Демонстрация принимает устойчивый параметр `state`. Примеры:

- <a href="demo/index.html?state=lisa-materials-ready">итоговые материалы и кнопка заказа</a>;
- <a href="demo/index.html?state=lisa-presentation-generating">подготовка презентации</a>;
- <a href="demo/index.html?state=lisa-presentation-ready-unread">готовая презентация и красная точка у колокольчика</a>;
- <a href="demo/index.html?state=lisa-notifications-list-unread">центр уведомлений</a>;
- <a href="demo/index.html?state=lisa-result-view-from-chat">просмотр результата из чата</a>;
- <a href="demo/index.html?state=lisa-presentation-email-sent">отправка презентации завершена</a>.

Неизвестное состояние не подменяется первым экраном: демонстрация выводит контролируемую ошибку, а профильная проверка завершается неуспешно.

## Слои пакета

- `source/` — договоры, схемы внутри пакета, происхождение компонентов и шрифт. Два SVG-компонента подключены к принятому HTML: адаптированная [оболочка телефона](source/components/lisa-phone-shell.svg) и созданный для DataCanvas [колокольчик уведомлений](source/components/lisa-notification-bell.svg). [Карточка презентации](source/components/lisa-presentation-card.svg) сохраняется как справочный компонент происхождения и не является отдельным визуальным источником итогового кадра.
- `demo/` — автономная интерактивная демонстрация, созданная из договоров и подтверждённая владельцем; именно принятый HTML является канонической визуальной поверхностью для кадров.
- `derived/` — производные `SVG`- и `PNG`-кадры из браузерных снимков принятого HTML. Они не собираются независимо из справочной карточки и вручную не редактируются.
- `evidence/` — свежие снимки настоящих браузеров, размеры, контрольные суммы и отчёты проверок.

## Команды

```bash
npm run generate:presentation-link-lisa-user-journey
npm run update:presentation-link-lisa-user-journey:evidence
npm run check:presentation-link-lisa-user-journey
npm run validate:presentation-link-lisa-user-journey
npm run validate:presentation-link-lisa-user-journey:evidence
npm run validate:presentation-link-lisa-user-journey:profile
npm run test:presentation-link-lisa-user-journey:browser
```

Сначала изменяется канонический договор, затем повторно создаются демонстрация и производные файлы. Перед каждым производным кадром генератор включает технический режим без начальной программной установки фокуса, дожидается загрузки шрифта, восстанавливает нижний якорь только у помеченной прокручиваемой области, снимает случайный программный фокус и пропускает два кадра стабилизации. Обычная интерактивная демонстрация сохраняет перенос фокуса при переходах пользователя. Правило одинаково применяется при создании производных кадров и браузерных доказательств, поэтому загрузка шрифта и перерисовка контура фокуса не меняют кадр между запусками, а экраны без нижнего якоря не прокручиваются. Прямо открытое состояние не запускает автоматическую последовательность, поэтому часы имеют проверяемый режим `static`. Генератор не передаёт Playwright явный параметр служебного стиля для снимка. При этом WebKit внутри Playwright пытается применить собственный встроенный стиль; политика безопасности страницы отклоняет эту попытку, а проверка допускает только точное известное сообщение об этом и завершает работу при любом ином сообщении консоли.

Канонические кадры создаются в WebKit через фиксированный виртуальный адрес `http://lisa.invalid`. Все запросы этого адреса перехватываются Playwright и обслуживаются только файлами переносимого пакета; выхода во внешнюю сеть нет, а выход за каталог пакета блокируется. Chromium остаётся обязательным движком для полного функционального, геометрического и доступностного прогона, WebKit — для канонического кадра и критического междвижкового маршрута. Основной браузерный профиль использует тот же виртуальный адрес, а отдельный тест подтверждает реальное открытие через `file://`. Независимые тесты распределяются между двумя изолированными процессами, чтобы ограничить срок жизни одного процесса WebKit; повторные попытки отключены, а нестабильный результат считается ошибкой. Карточки уведомлений используют обычную сплошную CSS-рамку без зависящей от компоновщика внутренней тени; вторичные кнопки сохраняют внутреннюю линию. Это разделение закреплено визуальным договором и устраняет обнаруженную межпроцессную разницу единичных пикселей карточки. Повторный запуск генератора не должен создавать отличий.

## Границы чтения результата

- Надпись «20 минут» — текст интерфейса прототипа, а не утверждённое соглашение о времени готовности.
- Восемь секунд — только сжатая длительность автоматического показа в демонстрации.
- Красная точка, правила прочтения уведомления, устранение дублей, повторные попытки и состав одного почтового сообщения — решения прототипа, а не новые продуктовые требования.
- Полный адрес защищённой ссылки в интерфейсе не показывается; карточка и уведомление дают действие для открытия той же нередактируемой `PDF`-копии.
- Точные правила доступа, срок жизни ссылки, порядок двух проекций готовности, несколько устройств и разделение ответственности смежных команд остаются открытыми продуктовыми решениями.
