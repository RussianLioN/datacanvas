# Пользовательский путь заказа презентации

Навигация: [DataCanvas](../../../../README.md) / [Документация](../../../README.md) / [Продукт](../../README.md) / [Аналитика](../README.md) / [Путь заказа презентации](README.md) / Пользовательский путь

## Назначение

Документ описывает опубликованный автономный прототип Лисы: десять исходных
экранов и три экрана статусов в конце маршрута. Это **исторический выпуск**;
его прежние данные, тексты и разрешение выпуска ниже сохранены как свидетельство,
а не как разрешение на новый выпуск для ООО «Водолей Трейд». Точный машинный состав
исторического выпуска закреплён в [реестре активных договоров](source/active-contracts.json)
и [договоре пути](source/journey-contract.json).

Пять текстов будущего кандидата — подпись кнопки, сообщения начала и успеха,
тема и тело письма — находятся в [реестре утверждённых текстов](owner-approved-texts.md).
Изолированный черновик маршрута из 13 экранов принят для документального
каскада и зафиксирован его [манифестом](candidate-evidence/prototype-draft/manifest.json).
В нём заменены 11 изменяемых кадров, а два исходных экрана сохранены без
перерисовки.
Новый визуальный выпуск блокируется до завершения каскада и отдельного итогового
подтверждения Владельца. Для мобильных кадров Лисы и письма применён SVG-first.
Три готовых PDF ООО «Водолей Трейд» образуют отдельную ветвь: они преобразуются
штатным контролируемым импортёром в PNG без пересборки текста и макета по
[договору импорта PDF](source/presentation-pdf-raster-import-contract.md).
Очищенная справка по ООО «Водолей Трейд» заменяет данные ГК Достовалова только
внутри существующих групп SVG мобильных кадров.

## Действие заказа

Действие `order-presentation` доступно только на экранах 2–4. Для Q4_2026 оно
сразу отправляет допустимый заказ без предпросмотра и второго подтверждения.
Доступность действия определяется вариантом жизненного цикла, а не линейным
порядком демонстрационных экранов: до принятия заказа кнопка доступна, после
принятия блокируется для пары сеанс/пользователь. Если запрос не принят, после
исправления данных действие снова доступно; второй заказ после принятия не
создаётся.

## Исторический контрольный просмотр Product Owner

Статус содержания: согласовано. Статус визуального выпуска: согласовано. Этот
абзац описывает только исторический выпуск, чьи точные тексты сообщений вошли в
договор и для которого были разрешены штатная генерация финальных HTML, SVG, PNG,
архива и снимков браузера. Он не переносит это разрешение на будущий кандидат.

Все существующие десять экранов сохраняются в исходном порядке. Три экрана с
действием заказа остаются частью этого маршрута, а не заменяют его. После
нажатия действие становится неактивным для пары сеанс/пользователь и маршрут
продолжается по существующим экранам формирования, чата, отправки и презентаций.
Дополнительные экраны статусов добавляются только после отображения презентаций.
Каждый статусный экран создаётся штатным генератором из канонического SVG-исходника
`7.2` с погашенной кнопкой: согласованный текст заменяет содержимое существующих
групп строк внутри SVG с тем же стилем, цветом и прозрачным фоном, затем SVG заново
растрируется в три PNG-сегмента. HTML, CSS и добавочный SVG не накладывают на экран
дополнительную карточку или иной текст. Для частичной доставки прототип показывает
безопасный пример подстановки `OMEGA` и `SIGMA`; правило подстановки в продукте
остаётся привязанным к фактическому поиску адресов.

Для полной недоставки нет согласованного текста и отдельного кадра. До отдельного
двухфазного обсуждения и выбора владельца этот случай не включается в будущий
прототип и не подменяется сообщением частичной доставки.

В историческом выпуске были согласованы точные тексты начала, успеха, задержки,
частичной доставки и непринятого запроса, а также сохранение безопасного состояния
в том же чате без PUSH. Product Owner одобрил тот выпуск и его визуальную
публикацию. Будущий кандидат использует отдельный реестр утверждённых текстов и
должен пройти новый покадровый цикл до пересборки и публикации.

По отдельному положительному решению Product Owner оба статуса исторического
выпуска имеют значение `approved_product_owner`; для него были выполнены
окончательная визуальная генерация и проверки браузера. Будущий кандидат не
наследует эти статусы.

## Сохранение вида и навигации

Черновик сохраняет внешний вид и навигацию исторического прототипа: телефонные
состояния остаются прокручиваемыми, письмо показано отдельным кадром, а каждый
вариант презентации состоит из трёх страниц с внутренней прокруткой. Точные
размеры, правила размещения и проверки находятся в технических договорах
[визуальной основы](source/visual-basis-contract.json) и
[поэкранной подготовки](source/canonical-svg-frame-pipeline-contract.md).

## Исторические критерии выпуска

Следующие критерии относятся только к опубликованному историческому выпуску.
Они не подтверждают новый кандидат ООО «Водолей Трейд» и не разрешают его выпуск.

1. Активный реестр содержит ровно тринадцать состояний: десять исходных в указанном
   порядке и три канонических статусных экрана в самом конце.
2. Старые двадцать состояний не видимы как активный маршрут.
3. Все три кнопки заказа ведут в `lisa-presentation-generating`.
4. Все тринадцать визуальных источников имеют закреплённые SHA-256 в каталоге
   рендеров; для трёх исходных PDF отдельно закреплены SHA-256 и сведения о страницах.
5. Переносимый архив использует только файлы из собственного корня и `assets/**`; он не зависит от `source/**` во время исполнения.
6. Системная строка и домашний индикатор не меняют положение при программной прокрутке, колесе и перетаскивании средней области на экране 3.
7. В исполняемом пакете находятся 27 телефонных PNG-сегментов, один PNG экрана
   почты и три PNG вариантов презентации; полных телефонных PNG, сырых SVG и
   исходных PDF нет.
8. Телефон центрируется в визуальном фрейме справа от служебной панели при изменении размера окна.
9. Верхние и нижние углы телефона обрезаются по одному исходному радиусу; внешняя оболочка не создаёт второй рамки или отличающихся боковых полос.
10. Почтовое изображение полностью заполняет собственную сцену 1553×1013 без внутренних полей, обрезания и искажения.
11. Каждый из трёх вариантов презентации содержит ровно три страницы и прокручивается только внутри окна 960×540.
12. Стрелки проходят десять исходных экранов, затем три экрана статусов; стрелка вправо неактивна только на экране частичной доставки.
13. При изменении размеров браузера каждый слайд автоматически меняет размер, сохраняет пропорции 16:9 и целиком помещается в окно презентации.
14. Доказательства визуальной проверки содержат 39 свежих WebKit-снимков: каждый из тринадцати экранов показан в размерах `1280×720`, `390×844` и `320×568`; манифест фиксирует путь и SHA-256 каждого снимка.
