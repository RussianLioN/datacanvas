## Назначение

Документ подготавливает раунд оценки ПШЕ — трудозатрат в человеко-днях — для `DC-ST-23` - `DC-ST-28` — P1-историй запуска DataCanvas другим агентом.

Численные оценки в этом документе не назначены. Их должна заполнить команда реализации по аналогии с сохраненным Excel-источником [bl-value-rm-data-canvas.xlsx](../../sources/raw/bl-value-rm-data-canvas.xlsx) и его ресурсной матрицей.

## Источник Матрицы

Excel-источник содержит один лист `Лист1`. В строках 4-25 находятся исходные истории DataCanvas, а в строке 3 — заголовки колонок оценки:

- `Название Story` — исходная формулировка истории.
- `Комментарии` — функциональная зона или уточнение.
- `Бизнес ценность` — ожидаемая ценность.
- `Приоритеты` — приоритет истории.
- `Срок` — плановый ориентир из Excel.
- `ПШЕ` — итоговая оценка трудозатрат.
- `БА`, `СА ЕФС`, `PL ЕФС`, `Дизайн`, `ВН ЕФС`, `Смежный сервис`, `СА Оркестратор`, `DEV Оркестратор`, `СА AEF Containers`, `DEV AEF Containers`, `QA`, `AQA`, `НТ` — рольные компоненты оценки.

В Excel строка 1 показывает реалистичный сценарий с коэффициентом `2`, строка 2 — базовый итог по ролям. Для новых строк `DC-ST-23` - `DC-ST-28` нужно сохранить ту же структуру: сначала оценить рольные компоненты, затем посчитать итоговую ПШЕ.

## Правила Оценки

- Не переносить автоматически ПШЕ из похожих Excel-строк.
- Не выводить оценку по догадке из текста истории, BMC, Vision, ADR, schemas или scripts.
- Для каждой истории указать рольные компоненты, итоговую ПШЕ, источник аналогии и комментарий команды реализации.
- Если команда считает, что история требует архитектурного решения до оценки, в строке фиксируется статус `блокер оценки`, а не числовая оценка.
- После заполнения оценок нужно вернуться к [кандидатному плану спринтов](sprint-candidate-plan.md) и проверить емкость, резерв, ограничения и вытеснение работ.
