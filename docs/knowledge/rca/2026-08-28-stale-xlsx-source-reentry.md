# RCA: Повторное Попадание Устаревшего XLSX От 2026-08-17

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / повторное попадание устаревшего XLSX от 2026-08-17

Статус: исправлено проверочным барьером
Дата: 2026-08-28
Владелец: Documentation Owner / Process Owner

## Симптом

После появления санитарной копии XLSX от 2026-08-19 старый общий XLSX от
2026-08-17 мог снова использоваться как текущий вход каскада. Это создавало
риск построить конус влияния по историческому источнику и получить формально
успешный запуск с неверной базой продукта.

## Воспроизведение

1. Выбрать trigger-путь к незарегистрированному или историческому XLSX.
2. Запустить `npm run cascade:run` с актуальным Git-диапазоном и этим trigger.
3. До исправления маршрут мог перейти к fallback-логике по целевому документу
   вместо жесткой проверки идентичности источника.

## Пять Почему

1. Почему исторический XLSX мог вернуться? Потому что запуск доверял пути
   trigger без обязательной связи с активным реестром источников.
2. Почему связь не была обязательной? Потому что fallback для обычного
   документа применялся слишком широко.
3. Почему fallback задел XLSX? Потому что классы `xlsx`, `provenance` и
   `source_registry` не были отделены как чувствительные источники.
4. Почему это не ловилось раньше? Проверка смотрела на наличие Git-изменения,
   но не доказывала идентичность источника из текущего реестра.
5. Почему риск повторяемый? Исторические XLSX остаются в репозитории как
   свидетельства и похожи на рабочие входы по имени и структуре.

## Корневая Причина

Чувствительные входы каскада не имели fail-closed правила: XLSX, provenance и
реестр источников должны разрешаться только через активный источник или точный
delta-манифест реестра, без fallback по `target_artifact`.

## Исправление

`resolveSourceIdentities` и `resolveActualTriggerPaths` проверяются так, что
незарегистрированный XLSX не переходит к legacy fallback. Планировщик разрешает
fallback только для нечувствительных документов.

## Исполняемый Барьер

- `npm run validate:cascade-vnext` отклоняет незарегистрированный XLSX и
  подмену replay-входов.
- `npm run validate:cascade-vnext-e2e` проверяет тот же отказ во временной
  рабочей копии.
- `npm run validate:xlsx-backlog` остается профильным барьером текущей
  санитарной копии 2026-08-19.

## Остаточный Риск

Если будущий исторический XLSX будет ошибочно зарегистрирован как текущий
источник, этот RCA сам по себе не остановит смысловую ошибку. Такой случай
должен блокироваться проверкой реестра продуктовых источников и решением
владельца по статусу источника.
