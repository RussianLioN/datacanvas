# RCA — барьер частичной публикации cascade:complete

## Симптом

Отказная ветка `cascade:complete` могла сформировать запись журнала с
`evidence_path`, хотя каталог доказательств не был атомарно опубликован. Такой
путь выглядел как достижимое доказательство, но фактически был фантомной
ссылкой.

## Воспроизведение

1. Запустить `cascade:complete` для кандидата, у которого один из командных
   барьеров возвращает ошибку.
2. Проверить диагностический журнал, выведенный перед отказом.
3. До исправления запись содержала путь к `completion-evidence.json`, хотя
   публикация пакета не выполнялась.

## Пять Почему

1. Почему появился фантомный путь? Журнал создавался до успешной атомарной
   публикации.
2. Почему отказная ветка использовала тот же путь, что успешная? Построитель
   записи журнала не различал опубликованное и ещё не опубликованное
   доказательство.
3. Почему это не ловилось проверкой? Тест проверял отсутствие частичного
   каталога, но не проверял содержимое отказного журнала.
4. Почему ссылка считалась допустимой? Контракт журнала разрешал nullable path,
   но не задавал правило, что путь допустим только после успешной публикации.
5. Почему риск повторяемый? Все будущие отказные ветки могли копировать тот же
   порядок: сначала рассчитать путь, потом сорваться до публикации.

## Корневая Причина

Граница между вычисленным будущим путём и реально опубликованным доказательством
не была закодирована в общем построителе журнала запуска.

## Исправление

`buildRunLedgerEntry` сохраняет `evidence_path` только для статуса `passed`.
Для `failed` и `blocked` журнал содержит `evidence_path: null` и, при наличии
подтверждённой повторяемой причины, достижимый `rca_path`.

## Исполняемый Барьер

`npm run validate:cascade-vnext` проверяет, что отказная запись журнала не
содержит путь к несуществующему evidence и что указанная RCA-ссылка ведёт к
существующему техническому RCA.

## Остаточный Риск

Общий runbook для ручного разбора отказных каскадов ещё не оформлен. Риск
зарегистрирован как остаточный и не устраняется в этой задаче, чтобы не
расширять область правки.
