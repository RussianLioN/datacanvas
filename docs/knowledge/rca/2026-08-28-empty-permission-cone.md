# RCA: Нулевой Конус Реестра Разрешений

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / нулевой конус реестра разрешений

Статус: исправлено проверочным барьером
Дата: 2026-08-28
Владелец: Documentation Owner / Process Owner

## Симптом

Правка реестра разрешений могла давать пустой конус влияния. В результате
каскадный запуск выглядел завершенным, хотя фактически не доказывал влияние на
требования, истории, договоры, выпускные свидетельства и архив.

## Воспроизведение

1. Изменить реестр, который управляет разрешением выпуска или приемкой.
2. Запустить планирование каскада с этим путем как trigger.
3. До исправления анализ мог не найти downstream-обязательства и перейти к
   состоянию без реальной проверки зависимых артефактов.

## Пять Почему

1. Почему конус был пустым? Потому что измененный реестр не был связан с
   зависимыми артефактами как авторитетный управляющий вход.
2. Почему связь не сработала? Потому что проверка маршрута принимала пустой
   результат как допустимую диагностику.
3. Почему пустой результат опасен? Потому что отсутствие обязательств
   маскирует неполную публикацию или подмену состава.
4. Почему это повторялось? Реестры разрешений воспринимались как служебные, а
   не как входы, влияющие на выпускной пакет.
5. Почему прежних проверок было недостаточно? Они проверяли структуру
   артефакта, но не доказывали полный реестр входов и выходов кандидата.

## Корневая Причина

Каскад не связывал фактический состав кандидата с неизменяемым отпечатком и не
требовал одинаковый отпечаток в run record, diff-манифесте и evidence.

## Исправление

Финализация строит `candidate_fingerprint_sha256` из candidate SHA, входных
путей, выходных путей и фактических Git-изменений. Профильная проверка,
завершение и печать завершения сверяют тот же отпечаток; подмена состава
выходов меняет отпечаток и блокирует цепочку.

## Исполняемый Барьер

- `npm run validate:cascade-vnext` проверяет стабильность отпечатка и отказ при
  подмене состава.
- `npm run validate:schemas` требует наличие отпечатка и реестров входов/выходов
  в `cascade-actual-diff-manifest`.
- `npm run validate:cascade-vnext-e2e` проверяет совпадение отпечатка в полном
  жизненном цикле после коммита изменений.

## Остаточный Риск

Отпечаток доказывает состав кандидата, но не заменяет смысловое решение
владельца. Если реестр разрешений изменен корректно по форме, но ошибочно по
смыслу, нужно отдельное согласование владельца.
