# RCA: низкое разрешение внешних кадров браузерного прототипа Лисы

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / Низкое разрешение внешних кадров браузерного прототипа Лисы

## Симптом и воспроизведение

Письмо и презентации на внешних кадрах браузерного кандидата были нечёткими
при локальном увеличении. Повторение: открыть письмо или презентацию из
браузерного кандидата и проверить натуральный размер ресурса — письмо имело
`1280×960`, а одна общая картинка каждой презентации — `960×1620`.

## Пять причин

1. Генератор копировал внешние PNG из исторического `prototype-draft`.
2. Исторический пакет предназначался для чернового просмотра, а не для 4K.
3. Одна вертикальная картинка использовалась для всех трёх страниц презентации.
4. Браузерная логика смещала эту картинку, не меняя сам ресурс страницы.
5. Валидатор требовал байтового совпадения с историческим PNG вместо проверки
   источника, формата, натурального размера и контрольной суммы нового ресурса.

## Корневая причина

Договор браузерного кандидата не описывал самостоятельный контур внешних
ресурсов с разрешением, происхождением и приёмкой. Поэтому генератор и
валидатор считали низкокачественный исторический PNG единственным допустимым
источником.

## Отвергнутые гипотезы

- Масштабирование CSS не создаёт недостающие пиксели и не устраняет размытость.
- Прямое открытие исходного PDF в браузере нарушает запрет на передачу и
  публикацию локальных PDF, поэтому не допускается.
- Увеличение старых PNG ухудшало бы качество, поэтому запрещено.

## Исправление и предотвращение

В договор добавлен профиль внешних 4K-ресурсов. Отдельный генератор проверяет
SHA-256 трёх локальных PDF, выводит для каждой презентации три PNG
`3840×2160` через Swift/CoreGraphics, строит обзорный лист `3840×6480` и не
сохраняет путь к PDF. Письмо копируется как принятый SVG и отдельно
растеризуется в `3840×2880` только для приёмки. Браузер подставляет текущую
страницу по её собственному пути.

Шлюз предотвращения состоит из проверок схемы, контрольных сумм, натуральных
размеров, безопасного SVG без внешних ссылок, отсутствия старых внешних PNG и
браузерной проверки переключения страниц в Chromium и WebKit без сети.

## Закрытие

3 сентября 2026 года владелец принял внешнюю 4K-серию вместе с браузерным
прототипом как финальный чистовой результат. Решение хранится отдельно от
сгенерированного манифеста; валидатор сверяет его с договором, всеми четырьмя
экранами, манифестом, отпечатком кандидата и архивом поставки. Исходные PDF
по-прежнему не входят в Git, HTML-прототип или архив.
