# RCA: Разрыв Проверки Компоновки Визуального BMC

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / Компоновка визуального BMC

Дата: 2026-07-12
Связанное изменение процесса: `PROC-063` — блокирующая проверка компоновки визуальных артефактов.

## Ошибка

Канонический SVG и созданный из него PNG проходили полный BMC-gate, хотя текст блоков `B7`, `B6` и `B2` выходил за нижние границы рамок. Визуальное пересечение было заметно при открытии PNG, но не обнаруживалось автоматическими проверками.

Дополнительно актуальный BMC manifest включал browser/PDF raster snapshots прежней версии. Эти файлы были корректным историческим evidence своего спринта, но не подтверждали текущий BMC.

Навигационная страница BMC показывала сырые пути вместо кликабельных ссылок и не отображала актуальные рендеры. Из-за этого пользователь открыл SVG из старой рабочей ветки и увидел ранее исправленное переполнение как будто оно относится к текущему кандидату.

## Влияние

- Пользователь мог получить формально принятый, но визуально непригодный BMC.
- Проверка воспроизводимости создавала ложное ощущение полной визуальной проверки.
- Старые снимки могли быть ошибочно восприняты как доказательство текущего продуктового содержания.
- Отсутствие предпросмотра на навигационной странице затрудняло различение актуального и устаревшего рендера.

## 5 Почему

1. Почему текст вышел за рамки? Генератор переносил строки по примерному числу символов и не учитывал доступную высоту блока.
2. Почему генератор не остановился? В нём не было минимального размера шрифта, расчёта последней строки и запрета публикации при переполнении.
3. Почему валидатор пропустил дефект? Он проверял структуру, наличие девяти блоков, минимальный размер шрифта и возможность отрисовать SVG, но не измерял координаты текста относительно рамок.
4. Почему PNG/PDF не помогли обнаружить проблему? Проверка свежести доказывала происхождение переносимых файлов из SVG, но не качество компоновки самого SVG.
5. Почему старые снимки оставались текущим evidence? Генератор автоматически включал существующие файлы в manifest по факту их наличия, не проверяя, к какой версии источника они относятся.

## Корневая Причина

Контракт визуального качества был структурным, но не геометрическим. Система проверяла наличие и воспроизводимость файлов, а не пригодность готового кадра для чтения. Исторический evidence не был отделён от текущего acceptance package.

Дополнительная межплатформенная причина обнаружена в CI: контракт ошибочно считал побайтовое совпадение PNG/PDF доказательством визуального соответствия. Разные версии `rsvg-convert` создают разные внутренние байты переносимых файлов из одного и того же SVG. Генератор из-за этого переписывал корректные файлы в Linux, а проверка чистоты рабочей копии блокировала процесс.

## Исправление

- Генератор рассчитывает переносы и размер шрифта по ширине и высоте каждого блока и прекращает работу, если текст не помещается.
- Сетка BMC использует одинаковые интервалы между колонками, составными блоками и рядами.
- Валидатор разбирает готовый SVG и проверяет границы текста, рамок, пересечения, интервалы и холст.
- PlantUML получает ограниченные по длине строки и проверку полной сетки.
- Отрицательные тесты доказывают отказ при вертикальном переполнении, нарушении сетки, слишком длинной строке PlantUML и устаревшем PNG/PDF.
- Исторические browser/PDF raster snapshots исключены из текущего BMC manifest и помечены как историческое evidence.
- Неизменные PNG/PDF повторно используются только при точной связи хэшей с неизменным SVG и корректной структуре файлов.
- Свежий рендер проверяется независимо по размерам, непустому содержимому и пространственному распределению видимых элементов; корректная переупаковка тех же пикселей разрешена.
- Генератор применяет геометрический контракт к сформированным SVG и PlantUML до записи пакета, а растровый валидатор ищет видимые пиксели в защитной зоне за каждой рамкой.
- PNG сравнивается со свежим SVG-рендером отдельно по каждому из девяти блоков; PDF сначала растеризуется независимым PDF-движком и проходит ту же проверку.
- README BMC содержит относительные кликабельные ссылки и встроенные предпросмотры текущих SVG/PNG, а изображение PDF открывает текущий PDF-файл.

## Проверка Результата

Пройдены `npm run validate:bmc`, `npm run validate:artifact-registry`, `npm run validate:artifact-hashes`, `npm run validate:schemas` и `npm run validate:data-leakage`. PNG дополнительно открыт и проверен визуально в полном разрешении `3840x2160`.

## Предотвращение

- Любой новый визуальный формат получает явный контракт геометрии и отрицательные тесты до включения в актуальный пакет.
- Хэш, сигнатура файла и успешный рендер не считаются доказательством отсутствия переполнения.
- Побайтовое совпадение переносимых файлов между разными версиями системного рендера не используется как критерий визуального качества.
- Для каждого рамочного визуального артефакта обязателен отрицательный растровый тест с намеренно размещенными пикселями за границей рамки.
- Минимальный отрицательный сценарий использует темную полосу толщиной один пиксель непосредственно за рамкой; такой дефект блокируется без допуска.
- Отрицательные тесты обязаны доказывать отказ при удалении содержимого одного PNG-блока и при подмене PDF другим формально корректным документом.
- Историческое evidence связывается со своим запуском и не становится текущим только потому, что файл существует.
- Навигационная страница визуального пакета обязана показывать текущие рендеры и блокируется валидатором при возврате к сырым путям или служебным инструкциям.
- Для нового класса макета обязательна ручная визуальная проверка после автоматических gate; повторные изменения того же класса блокируются автоматическими геометрическими условиями.

## Ограничение

В репозитории хранится исходный PlantUML, но отдельный PlantUML-рендер не версионируется. Текущая проверка ограничивает строки и пространственные связи исходника. Если появится отдельный SVG/PNG, созданный PlantUML-движком, он должен быть зарегистрирован как новый производный артефакт и получить такую же проверку готового кадра.
