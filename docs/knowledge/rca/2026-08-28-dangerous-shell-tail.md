# RCA: Опасный Shell-Хвост В Проверочной Команде

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / опасный shell-хвост в проверочной команде

Статус: исправлено проверочным барьером
Дата: 2026-08-28
Владелец: Process Owner / Security Lead

## Симптом

Команда, начинавшаяся с разрешенного `npm run ...`, могла получить хвост вида
`; rm ...`, перенаправление или подстановку. Такая строка выглядит как
проверка, но фактически расширяет полномочия выполнения.

## Воспроизведение

1. Вставить в план или каталог команд строку `npm run validate:schemas; rm -rf ...`.
2. Запустить проверку каталога команд или построение validation manifest.
3. До исправления риск состоял в том, что доверие к префиксу `npm run` могло
   скрыть вредный хвост.

## Пять Почему

1. Почему хвост опасен? Потому что shell выполняет не только проверку, но и
   дополнительную команду.
2. Почему префикса недостаточно? Потому что `npm run validate:*` не ограничивает
   оставшуюся часть строки.
3. Почему это могло попасть в профиль? Потому что профильные команды приходят
   из машинного каталога и должны считаться недоверенным входом.
4. Почему обычный запуск рискованнее? Потому что выполнение через shell
   смешивает команду проверки и произвольный текст.
5. Почему это повторяемый класс ошибок? Похожие хвосты появляются при ручном
   копировании команд, объединении проверок и попытке добавить перенаправление
   вывода.

## Корневая Причина

Политика проверочных команд должна разбирать строку как строгий список
известных `npm run`-вызовов, а не доверять человекочитаемому тексту команды.

## Исправление

Проверочный профиль использует общий строгий разбор команд. Дополнительно
completion-профиль отказался от общего `npm test` и выполняет точный список
проверок через `spawnSync` без shell. Вложенное завершение каскада запрещено
отдельным барьером.

## Исполняемый Барьер

- `npm run validate:universal-documentation-workflow` содержит отрицательный
  тест на shell-хвост после разрешенного npm-префикса.
- `npm run validate:cascade-vnext` проверяет отказ от shell-хвоста,
  отсутствие полного `npm test` в completion-профиле и запрет вложенного
  `cascade:complete`.
- `git diff --check` остается отдельной командой без shell-склейки.

## Остаточный Риск

Если новая команда будет добавлена в `package.json` и каталог без профильного
разбора, она может стать новым доверенным входом. Поэтому новые команды должны
проходить через каталог и те же отрицательные проверки.
