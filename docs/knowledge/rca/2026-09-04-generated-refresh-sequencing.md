# RCA: параллельный запуск зависимых генераторов

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Знания](../README.md) / [RCA](README.md) / Последовательность производных обновлений

Дата: 2026-09-04
Область: `CO-2026-003` — заказ презентации из агента «Справка по клиенту», задача пересборки пакета Jira и связанных реестров.

## Симптом

Во время обновления пакета Jira проверка актуальности навигации и проверка манифеста хэшей получили состояние `stale` в параллельном наборе команд. В том же наборе профильная проверка навигации завершилась позже успешно. После последовательного запуска генераторов и проверок оба состояния стали актуальными без изменения ручных источников.

## Корневая причина

Порядок обновления производных артефактов был смешан с оптимизацией времени: навигация, архив и манифест хэшей были запущены как независимые операции, хотя манифест хэшей должен фиксировать уже завершённое состояние всех предыдущих производных файлов. Дополнительно проверка навигации запускает тест, который штатно пересобирает навигацию в рабочей копии; поэтому её нельзя считать независимой от проверки актуальности навигации.

## Почему проверка не остановила это раньше

Проверки корректно обнаруживали устаревшее состояние, но в рабочем порядке не было явного запрета на параллельный запуск зависимых генераторов и проверок с побочным обновлением производных файлов. Поэтому агент мог повторно создавать временную гонку даже при наличии правильных валидаторов.

## Предотвращающее действие

Для производных файлов действует обязательный порядок:

1. изменить ручные источники и договоры;
2. сформировать целевой артефакт штатным генератором;
3. обновить навигацию, если менялись документы или маршруты;
4. обновить архив, если менялся его состав или входные файлы;
5. обновить манифест хэшей последним;
6. проверить хэши отдельной последовательной командой.

Зависимые генераторы нельзя запускать параллельно. Параллельно допустимы только независимые проверки, которые не читают и не обновляют один и тот же производный файл.

## Проверочный минимум

- `npm run generate:docs-navigation -- --check`
- `npm run validate:documentation-archive`
- `npm run validate:artifact-hashes`
- `git diff --check`

## Остаточный риск

Если новый генератор или проверка с побочной пересборкой будет добавлена без явного положения в последовательности, риск может повториться. Поэтому договор генератора должен указывать входы, выходы и допустимые записи, а исполнитель должен запускать манифест хэшей последним. В задаче 9 плана необходимо отдельно устранить побочную запись из проверки навигации либо явно объявить её в договоре генерации.
