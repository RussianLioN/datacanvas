# RCA: сбор свидетельств параллельного обсуждения CO-2026-003

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [База знаний](../README.md) / [RCA](README.md) / Сбор свидетельств обсуждения CO-2026-003

Статус: активен

Дата: 2026-08-20

## Проблема

Во время первой фазы обсуждения тела письма отдельные временные файлы с
вариантами были записаны в рабочую копию по умолчанию, а не в целевую изолированную
рабочую копию изменения. Полный журнал и результаты не были потеряны, но такое
размещение могло смешать временные материалы с несвязанными локальными правками.

## Пять почему

1. Почему временные файлы попали не в целевую рабочую копию?
   В поручении был указан относительный путь.
2. Почему относительный путь оказался недостаточным?
   Параллельные исполнители имеют собственную рабочую копию по умолчанию.
3. Почему это не было остановлено до первой записи?
   Договор обсуждения описывал количество вариантов и анонимную оценку, но не
   способ разрешения пути для временных свидетельств.
4. Почему временные файлы могли повлиять на навигацию?
   Каждый Markdown-файл в обычном каталоге доступен генератору навигации как
   самостоятельный документ.
5. Почему итоговый источник оставался избыточным?
   Параллельные файлы сохранялись наряду с единым полным журналом, хотя для
   воспроизводимости достаточно единственного журнала из 380 вариантов.

## Корневая причина

Корневая причина — отсутствие в договоре проверяемого требования передавать
временным исполнителям абсолютный путь целевой изолированной рабочей копии и
сначала сводить их результаты в единый полный журнал, а затем удалять только
временные дубликаты.

## Исправление и предотвращение повторения

1. В [договоре обсуждения](../../product/analysis/presentation-link-lisa-user-journey/source/brainstorming-contract.json)
   закреплены правило абсолютного целевого пути на этапе выполнения и правило
   единственного полного журнала до очистки временных файлов.
2. [Схема договора](../../product/analysis/presentation-link-lisa-user-journey/source/schemas/brainstorming-contract.schema.json)
   требует оба правила; общая проверка схем валидирует сам договор.
3. [Генератор свидетельств тела письма](../../../scripts/generate-co-2026-003-email-body-brainstorm-evidence.mjs)
   формирует единый журнал с 19 разделами и 380 исходными вариантами, а
   проверка не допускает кандидата, которого нет в журнале.
4. [Проверки свидетельств](../../../tests/co-2026-003-brainstorm-evidence.test.mjs)
   подтверждают пять неактивных пакетов, 19 участников первой и второй фазы,
   30 кандидатов и блокировку визуального выпуска до решения владельца.
5. Все временные файлы, созданные до исправления, удалены только после сверки
   количества строк и сохранения единого журнала. Несвязанные локальные правки
   не удалялись.

## Исполняемые проверки

После изменения маршрутов или реестра порядок обязателен: сначала
`npm run generate:docs-navigation`, затем
`node scripts/generate-artifact-hash-manifest.mjs`, после чего выполняются
проверки без записи:

- `node --test tests/co-2026-003-brainstorm-evidence.test.mjs`;
- `npm run validate:co-2026-003-brainstorm-evidence`;
- `npm run validate:schemas`;
- `npm run generate:docs-navigation -- --check`;
- `npm run validate:artifact-registry` и `npm run validate:artifact-hashes`;
- `npm run validate:doc-links`;
- `git diff --check`.

## Остаточный риск и правило остановки

Если для новой фазы нельзя определить абсолютный путь целевой изолированной
рабочей копии до записи первого временного файла, фаза не запускается. Если
единый полный журнал не содержит ровно 19 разделов по 20 вариантов, центральная
консолидация и вторая фаза не начинаются. Это не разрешает рендер, архив или
изменение активного прототипа: до явного выбора владельца всех пяти текстов
блокировка выпуска сохраняется.
