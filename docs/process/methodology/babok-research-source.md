## Источник

Документ фиксирует очищенные выводы из двух пользовательских материалов:

- инструкции по применению BABOK-исследования как методического ядра агентной системы;
- исследовательского отчета о полной цепочке ИТ-продукта, роли бизнес-анализа, системного анализа, архитектуры, delivery, эксплуатации и AI-агентных требований.

Raw-файлы исследования не коммитятся как первичный проектный источник. В проект переносится нормализованная методика: правила, стадии, типы артефактов, трассировка и gates.

Машиночитаемый индекс нормализованных фрагментов хранится в `babok-research-source-index.json`. Индекс содержит fragment ids, применимость, locator и hash краткого правила без raw-копии исследования.

## Ключевые Выводы

1. Backlog не является самостоятельным источником истины.
   Он должен выводиться из стратегии, discovery, бизнес-требований, системных требований, моделей процессов и данных, архитектуры, НФТ, acceptance criteria и проверок.

2. Документация должна вести сквозной lifecycle:
   идея -> discovery -> бизнес-анализ -> системный анализ -> архитектура -> backlog -> delivery -> тестирование -> release -> эксплуатация -> change management.

3. Обязательная трассировка должна связывать:
   business need -> business requirement -> stakeholder requirement -> system requirement -> backlog item -> acceptance criterion -> test case -> release -> telemetry signal или KPI.

4. Бизнес-анализ отвечает за проблему, ценность, стейкхолдеров, процессы, границы, правила, метрики и связь с backlog.

5. Системный анализ отвечает за поведение системы, сценарии, данные, интеграции, ошибки, НФТ, интерфейсы, архитектурные модели и проверяемость.

6. Для AI-агентных решений дополнительно обязательны цель агента, tool policy, permission matrix, human approval gates, prompt/memory/retrieval policies, trace schema, eval dataset, guardrails, failure modes, explainability и AI risk register.

7. Агент документации может создавать черновики, проверки и отчеты о противоречиях, но не должен сам утверждать смысловые решения: смену приоритетов, удаление требований, закрытие открытых вопросов, изменение accepted BRD/SRS или ADR.

## Применение В DataCanvas

- BA/SA интервью продолжается только после проверки методики и связи с `PROC-039`.
- Product Change Order и cascade governance используют методику как quality gate, но не выводят бизнесовые решения без Product Owner.
- `Definition of Ready` и `Definition of Done` получают ссылку на методику для задач анализа, требований, backlog и AI-агентных изменений.
- Машиночитаемый слой хранится в `documentation-methodology-policy.json`.
