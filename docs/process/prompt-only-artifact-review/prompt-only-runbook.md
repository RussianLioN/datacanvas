# Runbook Prompt-Only Согласования Артефактов

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Процесс](../README.md) / [Prompt-only согласование артефактов](README.md) / Runbook

Статус: active
Владелец: Process Owner
Проверка: `npm run validate:prompt-only-artifact-review`

## Стартовый Запрос

Пользователь может запустить процесс одной фразой:

```text
Запусти prompt-only процесс согласования и редактирования артефактов проектной документации DataCanvas по docs/process/prompt-only-artifact-review/README.md.
```

После этого агент выполняет процесс сам: читает состояние, каталог ссылок и журнал решений, показывает пользователю текущий шаг и запускает нужные проверки без просьбы вручную вводить `npm` команды.

## Обязательная Последовательность

1. Прочитать `AGENTS.md`.
2. Прочитать `docs/process/prompt-only-artifact-review/README.md`.
3. Прочитать `artifact-review-session-state.json`.
4. Прочитать `artifact-edit-decision-ledger.md`.
5. Прочитать `artifact-link-catalog.json`.
6. Показать пользователю чек-лист шагов и текущий артефакт.
7. Показать ссылки группами: source — исходник, derived — производные файлы, evidence — доказательства, navigation — навигация.
8. Если вопрос касается существующего раздела, сначала показать текущий текст раздела.
9. Если согласуется формулировка, предложить не менее пяти готовых вариантов обычным русским текстом.
10. После явного выбора пользователя обновить только согласованные источники.
11. Для generated artifacts — автоматически созданных файлов — запустить генератор от источника и профильные проверки.
12. Обновить состояние, журнал решений и показать ссылки на измененные артефакты.

## Граница Смысла

Агент не принимает продуктовые решения и не добавляет продуктовые утверждения от себя. Содержимое Vision — видения продукта, BMC — Business Model Canvas, бизнес-модели продукта, историй, требований и спецификаций считается проверяемым содержимым документов, а не правилом workflow.

Если пользователь просит изменить смысл продукта, агент формулирует это как предлагаемую правку документа, показывает текущий текст, предлагает варианты и ждет явного согласования владельца.

## Политика Ссылок

- В сохраняемых файлах используются только относительные пути репозитория.
- В runtime chat — текущем ответе чата — агент строит абсолютные кликабельные ссылки на основе текущего рабочего каталога.
- Ссылки на производные файлы показываются вместе с источником и командой проверки.
- Если файл отсутствует, агент останавливает шаг и сообщает, какой источник или генератор нужно восстановить.

## Редактирование Производных Файлов

Generated artifacts — автоматически созданные файлы — всегда считаются представлениями, а не источниками правки.

Если пользователь просит изменить PlantUML — текстовую диаграмму, SVG — векторное изображение, PNG — растровое изображение, PDF — файл просмотра, или другой generated artifact — автоматически созданный файл:

1. Найти `source_path` в `artifact-link-catalog.json`.
2. Показать источник, производные файлы и политику редактирования.
3. Подготовить правку источника обычным русским текстом.
4. Получить явное согласование.
5. Изменить источник.
6. Запустить указанный `generator_command`.
7. Запустить `validation_commands`.
8. Показать ссылки на обновленные файлы.
9. Записать решение в `artifact-edit-decision-ledger.md`.

## Формат Вопроса Пользователю

Каждый вопрос должен начинаться с чек-листа:

```markdown
- [x] Прочитан runbook процесса
- [x] Показан текущий артефакт
- [ ] Получить решение владельца
- [ ] Обновить согласованные источники
- [ ] Запустить генераторы и проверки
```

Затем агент показывает:

- текущий текст раздела, если правится существующий раздел;
- короткий комментарий о причине вопроса;
- не менее пяти готовых вариантов текста, если согласуется формулировка;
- влияние выбора на исходные и производные артефакты;
- один ясный вопрос.

Сырой JSON, schema fragment — фрагмент схемы, или patch — техническая правка — не используются как основной текст вопроса.
