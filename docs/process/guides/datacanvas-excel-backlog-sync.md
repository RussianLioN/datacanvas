# Синхронизация Excel Backlog DataCanvas

Статус: active
Владелец: Product Owner / Process Owner
Проверка: `npm run validate:xlsx-backlog`, `npm run validate:product-sources`, `npm run validate:doc-links`, `npm run validate:docs-navigation`

## Назначение

Документ фиксирует правило работы с Excel backlog DataCanvas, когда нужно добавить, проверить или принять оценки ПШЕ — трудозатрат в человеко-днях — и затем синхронизировать проектную документацию.

Правило действует для файлов в `docs/product/sources/raw/` и `docs/product/sources/working/`. Сырой исходник Product Owner не редактируется. Рабочий файл создается в `docs/product/sources/working/` и регистрируется в `docs/product/sources/product-source-registry.json`.

Для DataCanvas текущая рабочая книга оценок — `docs/product/sources/working/datacanvas-backlog-draft-pshe-2026-07-08.xlsx`. Ее происхождение, допустимые изменения, SHA-256 и строки `DC-ST-23..DC-ST-29` — пользовательские истории запуска DataCanvas другим агентом и подготовки результата — фиксируются в `docs/product/sources/working/datacanvas-backlog-draft-pshe-2026-07-08.provenance.json`.

## Правило Точной Копии

Если задача — добавить строки в существующий Excel backlog, рабочая книга должна оставаться точной копией исходника и отличаться только согласованными добавленными строками.

Обязательные проверки:

- листы рабочей книги совпадают с исходником, если Product Owner отдельно не разрешил новые листы;
- принятая рабочая редакция исходных строк, колонок, формул, стили, цвета, ширины колонок, высоты строк, закрепление области, фильтры и комментарии контролируется валидатором; исключение — кешированные значения итоговых формул в строках 1-2, если они пересчитываются из-за добавленных строк и проверяются ожидаемыми итогами;
- низкоуровневые части `.xlsx` сохраняют исходные настройки листа: `sheetViews`, `pane`, `selection`, `sheetPr`, `sheetFormatPr`, `cols`, workbook defined names — именованные диапазоны книги — и связи с комментариями/VML;
- если исходная книга содержит активный фильтр и скрытые строки, рабочая книга сохраняет тот же смысл скрытия, расширяет диапазон фильтра только на добавленные строки и пересчитывает кешированные видимые итоги;
- новые строки наследуют стиль строки-аналога;
- формулы новых строк повторяют формульный паттерн исходника;
- общий диапазон формулы итоговой колонки расширяется только на добавленные строки и проверяется как ожидаемый диапазон;
- итоговые формулы и фильтры включают добавленные строки;
- статус черновой или неутвержденной оценки фиксируется в существующей структуре таблицы, если Product Owner не разрешил новые служебные колонки.

Недостаточно проверить только свойство `freeze_panes` или открыть книгу через библиотеку высокого уровня: такая перезапись может сохранить видимое значение закрепления, но изменить `selection`, `pane`, скрытые строки, служебные пути комментариев или кешированные итоги. Для рабочей книги DataCanvas такие параметры проверяются через XML-пакет `.xlsx`.

## Черновые Оценки

Черновая ПШЕ не является утвержденной оценкой команды реализации.

Для черновой оценки по аналогам нужно:

1. Выбрать строки-аналоги из исходного Excel.
2. Посчитать диапазон ПШЕ по этим аналогам.
3. Для рабочей строки выбрать консервативный профиль только как черновое значение, если Product Owner просит предварительное заполнение.
4. Зафиксировать статус рабочей оценки в provenance manifest — манифесте происхождения — или в существующей структуре таблицы, если Product Owner явно оставил такой способ.
5. Не хранить устаревающие служебные объяснения в комментариях ячеек, если они уже вынесены в machine-readable manifest — машиночитаемый манифест.

После проверки командой реализации черновые значения заменяются утвержденными значениями или фиксируется блокер оценки.

## Обратная Синхронизация Из Excel

Если команда изменила рабочий Excel на обсуждении, сначала нужно сравнить обновленный файл с последней рабочей версией и raw-источником.

Изменения классифицируются так:

- изменение ПШЕ, роли, комментария оценки или статуса утверждения — evidence для оценки и sprint planning;
- изменение текста истории, бизнес-ценности, приоритета, срока или границы продукта — смысловое изменение, требующее подтверждения Product Owner;
- изменение структуры таблицы, листов, колонок, формул или правил фильтрации — процессное или методическое изменение, требующее отдельной фиксации;
- изменение generated artifacts — автоматически создаваемых артефактов — не применяется вручную, а проводится через генераторы.

После подтверждения владельцев обновляются связанные артефакты по типу изменения. ПШЕ, рольные оценки, статус оценки и комментарии команды фиксируются в рабочей Excel-версии, манифесте происхождения, product backlog, профильном backlog-файле, sprint candidate plan, traceability и validation evidence. `docs/stories.md` и `docs/product/requirements/user-stories.md` обновляются только при смысловом изменении текста истории, бизнес-ценности, функциональной зоны, приоритета или границы продукта.

## Проверка В Репозитории И Локальный Навык

Обязательная проверка рабочей книги в этом репозитории:

```bash
npm run validate:xlsx-backlog
```

Команда запускает `scripts/validate-datacanvas-xlsx-backlog.py` и сверяет рабочую книгу с raw-источником, golden-описанием и provenance manifest — машинным манифестом происхождения. Проверка является частью `npm test`.

Для повторяемой работы установлен пользовательский навык Codex `datacanvas-xlsx-backlog-sync`.

Его нужно использовать, когда задача касается:

- проверки рабочей Excel-книги backlog DataCanvas;
- добавления новых строк в Excel backlog с сохранением формата;
- сверки формул, значений и стилей между raw и working Excel;
- переноса командных правок из Excel обратно в проектную документацию.

Навык не заменяет репозиторный gate — проверочный барьер — `npm run validate:xlsx-backlog`. Он помогает агенту выбрать правильный порядок работы с Excel, не забыть низкоуровневые проверки пакета `.xlsx` и провести обратную синхронизацию после командной оценки.

Для рабочей книги `datacanvas-backlog-draft-pshe-2026-07-08.xlsx` репозиторный валидатор дополнительно проверяет внутренние XML-блоки Excel: принятую рабочую настройку `sheetViews`, `pane`, `selection`, настройки `sheetPr`, `sheetFormatPr` и `cols`, диапазон `_FilterDatabase`, отсутствие устаревших комментариев H26-H32, скрытие строк 13-25, видимость строк 26-32 и кешированные видимые итоги.

## Минимальный Gate

Минимальная проверка после изменения Excel backlog:

1. Запустить `npm run validate:xlsx-backlog`.
2. Проверить JSON: `jq empty docs/process/universal-documentation-workflow/*.json docs/product/sources/product-source-registry.json docs/navigation/navigation-source.json`.
3. Запустить `npm run validate:product-sources`.
4. Запустить `npm run validate:product-source-consistency`.
5. Запустить `npm run validate:universal-documentation-workflow`.
6. Обновить generated navigation и hash manifest только генераторами.
7. Запустить `npm run generate:docs-navigation -- --check`, `npm run validate:doc-links`, `npm run validate:docs-navigation`, `npm run validate:doc-stale-status` и `npm run validate:artifact-hashes`.
8. Запустить `npm run scan:secrets`, `npm run validate:data-leakage` и `git diff --check`.
9. При широком влиянии запустить `npm test`.
