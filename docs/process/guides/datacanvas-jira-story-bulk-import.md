# Массовый импорт пользовательских историй DataCanvas в Jira

Навигация: [DataCanvas](../../../README.md) / [Документация](../../README.md) / [Процесс](../README.md) / Руководства / Массовый импорт пользовательских историй в Jira

Статус: active
Владельцы: Product Owner / Process Owner

## Назначение и граница

Руководство описывает ручной импорт подготовленного CSV в Jira. Пакет находится в состоянии `ready`, а утверждение о завершении — в состоянии `prepared`: это означает только готовность файлов и сопоставления. Сам импорт выполняется во внешнем интерфейсе и до отдельной фиксации результата не считается завершённым.

Машинное значение `selected_during_import` означает, что проект Jira нужно выбрать вручную во время импорта. Это значение не является ключом или названием проекта.

## Подготовка

1. Проверьте воспроизводимость CSV и готовность сопоставления:

   ```bash
   npm run validate:jira-story-import
   npm run validate:jira-field-mapping
   ```

2. Используйте файл `artifacts/generated/jira/datacanvas-stories-dc-st-23-dc-st-33.csv`. Не изменяйте его вручную: при изменении источника сформируйте файл штатным генератором.

3. Откройте в Jira средство массового импорта CSV и загрузите подготовленный файл.

4. На шаге выбора проекта вручную укажите фактический целевой проект. Не вводите `selected_during_import` как ключ проекта.

## Точное сопоставление

Сопоставьте пять столбцов с одноимёнными стандартными полями Jira:

- `Issue Type` — тип задачи — с полем `Issue Type`;
- `Summary` — краткое содержание — с полем `Summary`;
- `Description` — описание — с полем `Description`;
- `Priority` — приоритет — с полем `Priority`;
- `Comment` — комментарий — с полем `Comment`.

Для двух столбцов выберите пропуск импорта:

- `Story ID` — идентификатор пользовательской истории — пропустите; перед продолжением убедитесь, что идентификатор уже присутствует в `Summary`;
- `Target quarter` — плановый квартал — пропустите; перед продолжением убедитесь, что квартал уже присутствует в `Description`.

`Capacity contour` — контур ёмкости — запрещено добавлять, создавать как пользовательское поле, сопоставлять или заполнять: такого столбца нет в разрешённом CSV и для него нет подтверждённого источника данных.

## Проверка перед запуском

1. В предварительном просмотре должно быть ровно 11 пользовательских историй: от `DC-ST-23` — истории передачи запроса от другого агента — до `DC-ST-33` — истории уведомления и ссылки в Лисе.
2. Для каждой строки тип задачи должен быть `Story`.
3. Убедитесь, что поля `Summary`, `Description`, `Priority` и `Comment` заполнены, а `Story ID` и `Target quarter` отмечены как пропускаемые столбцы.
4. Ещё раз убедитесь, что поле `Capacity contour` — контур ёмкости — отсутствует.
5. Только после этой проверки запускайте внешний импорт.

## Фиксация результата

После завершения внешнего импорта отдельно сохраните проверяемый результат и сведения об исполнителе. Готовый пакет сам по себе не подтверждает импорт и не даёт основания менять `import_completion_claim` на `imported_by_external_agent`.
