# PROC-062: Безопасный XLSX-Источник И Чистая История Git

ID: `PROC-062`
Статус: accepted
Автор: Codex
Дата: 2026-07-12
Целевая версия процесса: `0.1.0`

## Проблема

Исходный Excel Product Owner был добавлен в рабочую ветку вместе со служебным локальным путем внутри `xl/workbook.xml`. Действующие проверки находили локальные пути в зарегистрированных файлах текущего дерева, но не проверяли каждый XLSX во всех коммитах кандидата на слияние. Зелёный CI поэтому не доказывал безопасность истории ветки. Дополнительное ревью выявило вторую ошибку: принятие рабочей редакции Product Owner было ошибочно представлено как согласование трудозатрат командой реализации.

## Решение

- Оригинальный XLSX с закрытыми метаданными не хранится в Git; его SHA-256 независимо закреплен в команде проверки и контракте генератора, а затем также сохраняется в машинном манифесте происхождения.
- Зарегистрированный генератор создаёт контролируемую копию и удаляет только namespace-independent элемент `absPath` из `xl/workbook.xml`.
- До создания копии генератор сравнивает внешний файл с независимо закрепленным SHA-256. Манифест, сформированный из другого файла, не может сам подтвердить собственное происхождение.
- Побайтовые хэши всех частей OOXML доказывают, что других изменений исходного пакета нет.
- `npm run validate:git-history-hygiene` проверяет каждый коммит диапазона `origin/main..HEAD` и блокирует старый raw-путь, локальные указатели и внешние связи внутри XLSX.
- `npm run validate:ci-exact-sha` подтверждает, что CI проверяет точный SHA кандидата.
- Результат CI от предыдущего SHA после замены или принудительного обновления ветки считается недействительным.
- Статусы Product Owner и команды реализации проверяются раздельно: `owner_approved` не разрешает `team_validation_status: approved` без отдельного командного согласования.
- Пока командная оценка ожидается, валидатор блокирует перенос ПШЕ в sprint backlog и Jira и требует статус `ready_for_team_review` для связанных элементов продуктового бэклога.
- Проверка, создающая временные файлы, объявляется как `isolated_runtime_check`, перечисляет разрешенные временные пути, требует очистку и не считается постоянным изменением проектных артефактов. Эти пути исключены из Git, поэтому прерванная проверка не загрязняет рабочее дерево неотслеживаемыми файлами.

## Граница Продуктового Смысла

Изменение не меняет Vision, BMC, пользовательские истории, бизнес-требования, критерии приемки, backlog, roadmap, приоритеты, сроки или ПШЕ DataCanvas. Допустимы только техническая очистка источника, обновление provenance, ссылок, каскадных контрактов и generated-навигации.

## Миграция

Старый raw-путь удаляется из итогового дерева и всей истории нового кандидата. Контролируемый XLSX, манифест происхождения, рабочий XLSX и его provenance регистрируются как отдельные созависимые артефакты. Текущие формулировки, приоритеты и черновые рольные значения ПШЕ остаются принятыми Product Owner как вход для проверки, но получают отдельный статус ожидания командной оценки. Основной PR создаётся из новой ветки от чистого `main`; старый PR с загрязнённой историей закрывается без слияния.

## Rollback

До слияния закрыть чистый PR и не возвращать загрязнённую ветку как кандидат. После слияния откатывать merge отдельным PR. Нельзя откатывать изменение ослаблением leakage, history, exact-SHA или XLSX-проверок.
