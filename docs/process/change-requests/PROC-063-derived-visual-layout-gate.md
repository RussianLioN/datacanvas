# PROC-063 — Блокирующая Проверка Компоновки Визуальных Артефактов

ID: `PROC-063`
Статус: accepted
Статус решения: accepted
Дата: 2026-07-12
Владелец: Process Owner / QA Lead

## Причина

Визуальный BMC проходил действующие проверки, хотя текст нескольких блоков выходил за рамки и пересекал соседние области. Проверки подтверждали наличие структуры, минимальный размер шрифта, возможность открыть SVG и соответствие хэшей, но не измеряли компоновку готового результата.

## Принятое Правило

- Генератор визуального артефакта обязан до публикации рассчитать размещение текста, затем самостоятельно прогнать полный геометрический контракт готовых SVG и PlantUML и после рендера вызвать независимую растровую проверку PNG/PDF. Команда генерации завершается ошибкой при любом нарушении. Недопустимо публиковать содержимое, которое не помещается при минимально допустимом размере шрифта.
- Профильный валидатор повторно проверяет готовый SVG или другой формат: границы заголовка и каждой строки текста, геометрию основных и внутренних прямоугольников, границы разделительных линий, отсутствие пересечений, равномерность сетки и нахождение всех элементов внутри холста.
- Для PNG и PDF генератор повторно использует сохранённый переносимый файл только при неизменном каноническом SVG, точном совпадении хэшей с манифестом и корректной структуре файла. При изменении источника, хэша или структуры выполняется повторная генерация.
- Профильный валидатор независимо создаёт свежий рендер из канонического SVG и проверяет размеры, непустое содержимое и пространственное распределение видимых элементов. Проверка выполняется отдельно для каждого из девяти блоков по количеству темных пикселей и их распределению внутри блока, поэтому удаление или подмена одного блока не скрывается общей площадью канвы. Побайтовое совпадение PNG/PDF между разными поддерживаемыми версиями системного рендера не требуется, потому что оно не является признаком одинакового визуального результата.
- Для готового PNG валидатор проверяет защитную растровую зону со всех четырех сторон каждой рамки. Для темных пикселей текста начиная с первого пикселя за рамкой действует нулевой допуск; отдельная более широкая зона контролирует любое заметное содержимое. Так фактическое переполнение текста обнаруживается независимо от расчетной модели ширины шрифта.
- Готовый PDF обязательно преобразуется независимым PDF-движком в PNG и проходит те же проверки защитных зон и соответствия каждого блока свежему SVG-рендеру. Сигнатура, размер файла и хэш без этой визуальной проверки недостаточны.
- Каждый переносимый формат проверяется отдельным отрицательным тестом на устаревший или повреждённый файл. Дополнительный положительный тест подтверждает, что корректная переупаковка PNG с неизменными пикселями не считается дефектом.
- PlantUML проверяется на ограничение длины строк, полноту блоков, пространственные связи и точное соответствие содержания каждому псевдониму блока. Простого наличия девяти номеров недостаточно: перестановка содержания между позициями блокирует проверку. Если в репозитории появляется отдельный PlantUML-рендер, для него добавляется профильная проверка геометрии готового изображения.
- Визуальные BMC-поверхности содержат только название и девять блоков бизнес-модели. Видимые подписи о методике, генераторе, каноническом формате или производных файлах запрещены; служебные сведения остаются в манифестах и evidence.
- `docs/product/bmc/README.md` служит человекочитаемой навигацией: содержит относительные кликабельные ссылки, встроенные предпросмотры актуальных SVG и PNG и кликабельный предпросмотр PDF. Команды генерации, сырые пути репозитория и ссылки на служебные JSON в эту страницу не включаются.
- Публичный PlantUML не содержит комментариев генератора или указаний по ручному редактированию.
- Исторические снимки остаются доказательством своего запуска, но не включаются в текущий acceptance manifest после изменения источника или генератора.
- Проверка хэша, существования или возможности открыть файл не заменяет проверку визуальной компоновки.

## Область Изменения

Правило относится к контуру проектной документации DataCanvas и не меняет продуктовый смысл Vision, BMC, пользовательских историй, требований, backlog или roadmap.

## Миграция

Текущий BMC перегенерирован. Для SVG добавлен расчет размещения и самопроверка генератора, для SVG и PlantUML — блокирующий валидатор с отрицательными тестами, для PNG/PDF — свежая проверка рендера, каждого отдельного блока, пространственного покрытия и защитных зон вокруг рамок. PDF дополнительно растеризуется независимым PDF-движком. Отрицательные сценарии отдельно сдвигают заголовок за холст, расширяют внутреннюю полосу и разделитель за рамку, помещают видимые пиксели за рамкой, удаляют содержимое одного блока, подменяют PDF, меняют местами смысловые блоки PlantUML и повреждают переносимые файлы. Проверка переупакованного PNG отделяет визуальную идентичность от случайного совпадения байтов. Навигационная страница BMC перегенерирована с прямыми ссылками и предпросмотрами. Старые browser/PDF raster snapshots помечены как историческое evidence и исключены из актуального BMC-пакета.

## Проверка

```bash
npm run generate:bmc -- --check
npm run validate:bmc-visual
npm run validate:bmc-render-parity
npm run validate:bmc-package
npm run validate:bmc
npm run validate:universal-documentation-workflow
npm run validate:process-change-ledger
npm run validate:artifact-registry
npm run validate:artifact-hashes
npm test
```

## Откат

До слияния изменения можно удалить одним коммитом. После слияния откат выполняется отдельным PR. Откат не должен возвращать исторические снимки в актуальный acceptance manifest, восстанавливать межплатформенное требование побайтового совпадения или заменять независимую свежую проверку PNG/PDF простым копированием существующих файлов.
